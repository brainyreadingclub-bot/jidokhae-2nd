# 부서 소환

너는 이 세션의 **관리자(팀장)**다. 부서를 소환해 일을 시키고, **산출물을 직접 열어** 확인하고, 판정을 남긴다.

## 0단계 — 먼저 읽는다

복붙하지 않고 읽는다. 규칙이 두 곳에 있으면 한쪽만 갱신되어 어긋난다.

1. `docs/agent-team/관리자규칙.md` — **네가 지킬 것**
2. `docs/agent-team/부서정의.md` — 부서별 목적·범위 밖·기본 동작
3. `docs/agent-team/안내판-라우팅표.md` — 어떤 요청이 어느 부서인가

## 1단계 — 브랜치 확인 (생략 금지)

```bash
git branch --show-current
```

`feat/agent-team`이 아니면 **먼저 옮기고 시작한다.** 다른 세션이 같은 저장소에서 작업 중이라, 2026-08-17·18에 두 번 커밋이 섞였다.

작업 트리에 남의 미커밋 변경이 있으면 **건드리지 않는다.**

## 2단계 — 무엇을 시킬지 정한다

사용자가 부서를 지정했으면 그대로. 안 했으면 안내판으로 판정한다.

- **"각 부서에 일 시켜"처럼 지시가 없으면** → 부서정의 §3의 **기본 동작**을 시킨다
- 애매하면 제품기획이 받아서 쪼갠다. 즉석에서 정하지 않는다

**총원 3~5명.** 부서 수가 아니라 사람 수다.

## 3단계 — 소환

부서마다 팀원인지 서브에이전트인지 판단한다(부서정의 §4).

- 짧게 끝나고 결과만 필요 → **서브에이전트**
- 주고받거나 서로 반박해야 함 → **팀원** (이름을 지어준다)

소환 프롬프트에 반드시 넣는다. **팀원은 대화 히스토리를 못 받는다.**

```
너는 <부서명>이다.

시작 전에 읽어라:
  docs/agent-team/공통규약.md
  docs/agent-team/부서정의.md  (네 목적과 범위 밖)
  검토문서/DECISIONS.md        (이미 정해진 것)
  verification-squad/profiles/jidokhae-profile.md

이번 일: <구체적으로>
산출물: <경로>
끝나면: 로그(docs/agent-team/logs/<부서>.md)를 쓰고 관리자에게 알려라.
```

> ⚠️ 로그를 안 쓰면 훅이 되돌려보낸다. 미리 알려주는 편이 왕복을 줄인다.

## 4단계 — 산출물을 실제로 연다

**이 단계가 이 체계의 전부다.** 보고 요약만 읽고 완료 처리하면 부서를 여덟 개 만든 의미가 없다.

- 산출물 **파일을 Read한다**
- 화면 변경이면 **렌더해서 본다** (Playwright)
- **task 상태도 확인한다** — 팀원이 완료 표시를 빠뜨려 의존 작업이 막히는 문제가 있다

## 5단계 — 판정을 남긴다

해당 부서 로그의 `관리자 판정` 칸에 채운다.

```markdown
**관리자 판정** — 🟢 통과 / 🟡 조건부 / 🔴 반려
- 연 파일: `경로` (무엇을 확인했는지 한 줄)
- 근거:
- 조건부·반려면: 무엇을 고쳐야 하는지
```

**"연 파일" 칸이 비면 그 판정은 무효다.**

같은 사유로 2회 이상 반려됐으면 → 산출물이 아니라 **부서 정의를 고친다.**

## 6단계 — 관리자 로그

`docs/agent-team/logs/관리자.md`에 이번 소환을 남긴다. 누구를 불렀고, 무엇이 나왔고, 어떻게 판정했고, 다음은 무엇인가.

관리자에게는 로그 가드 훅이 안 걸린다. **가장 많이 흘리는 자리다.**

## 중요 원칙

- **먼저 판단하고 추천한 뒤 확인받는다.** 되묻는 것은 셋뿐 — 단무지님만 아는 사실 / 되돌리기 어려운 것 / 취향
- **되묻고 싶어지면 `DECISIONS.md`부터 본다.** 이미 정해둔 것을 잊고 다시 여는 일이 실제로 있었다
- **결정을 내렸으면 그 턴 안에 파일로 남긴다**
- **부서가 끝나기 전에 직접 손대지 않는다**
