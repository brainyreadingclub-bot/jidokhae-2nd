# 지독해 카카오톡 메시지 라이팅 가이드 (v0.5)

이 문서는 지독해 카카오 채널로 나가는 모든 메시지의 작성 기준이다.
토스 UX Writing 원칙(2022, 김자유)을 참고해 지독해 상황에 맞게 재정의했다.

## 1. 전제

**회원층**: 2030이 대부분. (재윤 판단, 트레바리 등 국내 독서모임 서비스 주 이용층과 동일하다는 전제)

여기서 나오는 결론은 하나뿐이다 — **하지 말 것**의 범위.
- 관공서 말투(~통보드립니다, ~하시기 바랍니다) → 안 씀
- 유행어·밈 → 안 씀

연령대는 "무엇을 하지 말지"만 정해준다. "무엇을 할지"는 브랜드가 정한다.
같은 2030을 두고 트레바리는 진지한 톤을, 무신사는 건조한 톤을 쓰고 둘 다 통한다.

**지독해 보이스**: 지똑똑은 활기차되 과장하지 않는다.

**활기는 첫 줄과 마지막 줄에, 정보는 건조하게.** 인사와 마무리에서 캐릭터가 드러나고, 가운데 금액·일시·장소는 목록으로 담백하게 둔다. 이렇게 나누면 캐릭터가 살면서도 정보가 흐려지지 않는다.

```
똑똑! 우제님, 좋은 소식이에요.        ← 활기

■ 일시: 8월 12일 (수) 오후 7:00      ← 건조
■ 결제 금액: 12,000 (결제완료)

전날 저녁에 다시 알려드릴게요. 그때 봬요.   ← 활기
```

**발신 주체는 「지똑똑」이다.**
카카오 채널명이자 캐릭터다. 지독해 독서모임에서 사람들이 책을 읽고 이야기 나누며 즐거워하는 데서 태어난 **지독해 요정**이라는 설정이다. 회원이 카톡에서 보는 이름은 지독해가 아니라 지똑똑이다.

여기서 따라오는 것 하나 — **1인칭을 쓸 수 있다.** 운영자 1인칭이 부담스러운 이유는 아는 사람의 부탁이라 거절 비용이 비대칭이어서인데, 지똑똑은 실존 인물이 아닌 캐릭터라 그 문제가 없다. 회원이 부담 없이 넘길 수 있다.
단, **운영자 실명·개인 이미지는 여전히 쓰지 않는다.**

> 캐릭터를 문안에서 어떻게 드러낼지는 6장 참조 — **메시지를 `똑똑!`으로 연다.**

## 2. 코어밸류 (제안)

토스는 다섯 가지 코어밸류를 쓴다: Clear(명확한), Concise(간결한), Casual(친근한), Respect(존중하는), Emotional(공감하는).

지독해는 이 중 넷만 가져간다.

### 명확한
정확한 정보를 한 번에 이해되게. 모호한 단어를 쓰지 않는다.

### 간결한
회원은 카톡을 읽지 않는다. 훑는다. 필요한 만큼만 쓴다.

### 친근한
딱딱한 뉘앙스를 쉽게 고쳐 쓴다. 단, **친근함 ≠ 다정함**.
지독해의 친근함은 "격식을 안 차린다"는 뜻이지 "살갑게 군다"는 뜻이 아니다.

### 존중하는
전환시키고 싶은 마음에 비용을 숨기거나 혜택을 부풀리지 않는다.
신뢰는 쌓기 어렵고 무너지기 쉽다.

### (제외) 공감하는
토스는 정보 뒤의 감정에 공감하는 문장을 다섯 번째 가치로 둔다.
지독해는 이걸 코어밸류에서 뺀다. 감정을 다루는 건 브랜드 보이스와 충돌하고,
자동 발송 메시지에서 감정 표현은 대체로 공허해진다.

> 참고: 삼성은 신뢰가 최우선이라 불필요한 감정 표현을 줄이고 사실 중심 문구를 원칙으로 삼는다.
> 토스만 정답이 아니다.

## 3. 작성 원칙

토스의 8원칙 중 카카오톡 메시지에 실제로 적용되는 것만 추렸다.

### 3-1. 잡초 뽑기
넣든 빼든 의미 전달에 영향이 없는 단어는 제거한다.
글자 수를 줄이는 게 아니라 **의미 없는 단어**를 없애는 것이다.

### 3-2. 빈 문장 없애기
허전해 보인다는 이유로 문장을 덧붙이지 않는다.
같은 말을 제목과 본문에서 반복하지 않는다.

### 3-3. 핵심만 남기기
운영자는 맥락을 많이 알아서 다 설명하고 싶어진다.
회원이 이미 아는 정보는 과감히 생략한다. 지금 확인해야 할 것만 남긴다.
**정보를 덜어내는 게 더 친절할 때가 있다.**

> **근거 — 첫 줄은 잠금화면에서 약 20자에서 잘린다.**
> 회원이 메시지를 열지 말지는 그 20자에서 결정된다. 핵심을 앞에 두지 않으면 열리지 않는다.
> 실제 사례: `#{회원명}님, 대기 중이던 모임의 자리가 나서 참여가 확정되었습니다!` → 미리보기에는 `초록고래님, 대기 중이던 모임의 자…`까지만 보여, 서비스에서 가장 반가운 소식이 열기 전에는 전달되지 않는다.
> 이건 새 원칙이 아니라 **이 원칙을 지켜야 하는 이유**다.

### 3-4. 소리 내어 읽기
눈으로 읽어 괜찮아도 소리 내면 어색한 문장이 있다.
한자어, 문어체, 호흡이 긴 문장이 그렇다. 한 문장에 하나의 메시지만 담는다.

### 3-5. 강요하지 않기
권유와 강요는 다르다. "이 혜택을 놓치면 손해예요" 류의 문장은 쓰지 않는다.
마감 임박·잔여석 강조도 공포를 조성하는 방식이면 쓰지 않는다.
혜택은 그대로 전달하되 회원이 스스로 판단하게 둔다.

### 3-6. 다음이 예상되게
링크나 버튼을 누르면 무슨 화면이 나오는지 미리 알려준다.
"신청하기"를 눌렀는데 결제창이 뜨면 불안하다.

### 3-7. 모두가 아는 말로
연령·직군에 따라 이해가 갈리는 용어를 쓰지 않는다.
지독해 내부 용어는 처음 접하는 회원 기준으로 한 번은 풀어준다.

**내부 용어 목록: 미정 — 재윤 입력 대기**

> 확인된 위반 사례: `승격`(대기자가 확정으로 바뀌는 것). 회원은 자기가 어디서 어디로 올라갔는지 모른다.

## 4. 메시지 3층 구조

층은 **톤을 켤지 끌지**와 **어느 채널로 나가는지**로 나뉜다.

> **카카오 정책 확인일: 2026-08-07**
> 출처: [알림톡 심사 가이드](https://kakaobusiness.gitbook.io/main/ad/infotalk/audit) · [채널 메시지](https://kakaobusiness.gitbook.io/main/channel/run/message)
> 정책은 개정된다. 실제 반영 시점에 공식 문서를 다시 확인하고 이 날짜를 갱신한다.

### 층 A — 거래성 (신청 완료, 취소, 환불, 결제)

**가운데를 건조하게 둔다.** 회원이 알고 싶은 건 하나다 — 얼마가, 언제, 어디로.

지똑똑은 **첫 줄 인사와 마지막 줄 마무리에만** 나온다(§1). 금액·일시·장소 사이에 캐릭터가 끼어들면 정보가 흐려진다.

- 금액, 일시, 장소는 `■` 목록으로
- 환불 소요 기간과 규정을 눈에 띄게 (불안 제거)
- **아쉬운 소식에는 느낌표를 쓰지 않는다** (§6)

**채널 제약 — 알림톡**
- 회원의 행동(신청·결제·취소)에 대한 결과 통지라 정보성 요건을 자연히 충족한다
- 발송 근거를 본문에 밝힌다 — `○○에 신청하신 분께 보내는 안내입니다`
- 템플릿 사전 승인 필요. 변수 추가·문구 수정은 **재심사** 대상이다

### 층 B — 안내성 (리마인드, 안내)

**지똑똑 톤 그대로.** 층 A보다 활기를 조금 더 써도 된다 — 돈이 걸려 있지 않기 때문이다.

- 강조 타이틀에 핵심
- 과장·재촉 없이
- 이모지는 쓰지 않음 (카톡에서 광고 신호로 읽힌다)

**채널 제약 — 알림톡**
- **정보성 경계에 있다.** 회원이 한 행동(신청·참여)에 근거해야 한다. 근거 없이 보내면 광고성으로 반려된다
- 발송 근거를 본문에 밝힌다
- **앱 설치 유도로 읽힐 표현 금지** — 심사 반려 사유다. 웹 경로 표현만 쓴다
- 무료체험·할인쿠폰·포인트 적립을 조건으로 특정 행위를 유도하지 않는다 — 반려 사유다

### 층 C — 홍보 (모집, 소식)

**아직 쓰지 않는다.** 현재 모집 공지는 카카오톡 오픈채팅방으로 처리한다.

층 B와 톤은 같되, **채널이 다르고 법적 요건이 붙는다.**

**채널 제약 — 친구톡 (광고성)**
- **알림톡으로 보낼 수 없다.** 모집·홍보를 알림톡에 넣으면 반려되고, 반복되면 채널 전체가 제재를 받는다
- 채널을 **친구 추가한 회원에게만** 나간다. 알림톡과 도달 범위가 다르다
- **정보통신망법상 광고성 정보 표기 의무 3가지가 문구에 포함돼야 한다**
  1. 제목·발신 프로필 앞에 **`(광고)`** 표기
  2. **발신자 연락처** 표시
  3. **무료 수신거부 방법** 안내
- 사전 템플릿 심사가 없다. 대신 우리가 스스로 규율해야 한다

**시작 전에 정할 것**
- 발송 빈도 상한 (심사가 없으므로 정하지 않으면 늘어난다)
- 오픈채팅방과의 역할 분담 (같은 공지를 두 곳으로 보내면 둘 다 안 읽힌다)
- 층 A·B에서 지킨 원칙 중 무엇을 유지할지. **광고라고 §3-5(강요하지 않기)를 풀면 알림톡에서 지킨 것이 무의미해진다.** 같은 회원이 두 메시지를 다 받는다

## 5. 승인 템플릿 분류

채널에 승인된 템플릿 **23건**을 층별로 분류했다. 조회일 2026-08-07.

> ### 실제로 살아 있는 것은 5건이다
>
> | | 건수 |
> |---|:--:|
> | 채널에 승인된 템플릿 | **23** |
> | 그중 **코드가 실제로 발송하는 것** | **5** |
> | 승인돼 있으나 코드가 안 쓰는 것 | 18 |
>
> **문서보다 이 숫자가 중요하다.** 승인 템플릿 23건 중 22%만 살아 있고, 나머지는 이전 설계·미연결·솔라피 기본 샘플이다. 채널을 정리하지 않으면 다음에 문안을 볼 때 또 23건을 훑게 된다.

### 층 A — 거래성 (8건)

| 템플릿 | 코드 사용 |
|---|:--:|
| REGISTRATION_CONFIRM | ✅ |
| WAITLIST_CONFIRM | ✅ |
| WAITLIST_PROMOTED | ✅ |
| WAITLIST_REFUNDED | ✅ |
| TRANSFER_REQUESTED | — |
| TRANSFER_WAITLIST_REQUESTED | — |
| TRANSFER_WAITLIST_PROMOTED | — |
| TRANSFER_WAITLIST_CANCELLED | — |

> `TRANSFER_*` 4건은 계좌이체 경로용으로 만들어졌으나 코드가 호출하지 않는다. 계좌이체 신청 알림 발송 여부는 **보류(2026-08-07 운영자 결정)** 이므로 이 문서에서 다루지 않는다.

### 층 B — 안내성 (3건)

| 템플릿 | 코드 사용 | 비고 |
|---|:--:|---|
| MEETING_REMIND | ✅ | 결함 1 대상 |
| MEETING_REMIND(사본) | — | 중복. 정리 대상 |
| NEW_MEMBER_WELCOME | — | 가입 환영. 코드 미연결 |

### 층 C — 홍보 (0건)

현재 채널이 알림톡만 쓰므로 해당 없음.

### 미분류 (12건)

억지로 층에 넣지 않는다. 사유를 남긴다.

| 템플릿 | 미분류 사유 |
|---|---|
| WAITLIST_EXPIRED | **해당 기능이 없다.** 대기 응답 기한이라는 개념이 현재 구조에 없다 |
| TRANSFER_DEADLINE_WARNING | **해당 기능이 없다.** 입금 기한 6시간 경고 — 현재는 운영자가 월말에 일괄 확인한다 |
| TRANSFER_EXPIRED | **해당 기능이 없다.** 미입금 자동 취소를 하지 않는다 |
| TRANSFER_PENDING | **구 설계.** 금액 단위가 `콩`이다 |
| REFUND_ACCOUNT_RECEIVED | **구 설계.** 금액 단위가 `콩`이다 |
| TRANSFER_CONFIRMED | **정책상 발송하지 않는다.** 계좌이체 입금 확인 알림 금지(2026-04-23 확정) |
| POST_MEETING | **보류 — 삭제하지 말 것.** 원래 용도(모임별 후기)는 폐기했으나, **분기 만족도 조사**로 재활용하기로 방향을 잡았다(2026-08-09). 설계는 이번 범위 밖이다 |
| 결제 완료 (이미지) | 솔라피 기본 샘플. 우리가 만든 것이 아니다 |
| 인증번호 (이미지) | 〃 |
| 가입 환영 (이미지) | 〃 |
| 인증번호 | 〃 |
| 가입 환영 | 〃 |

> 미분류 12건 중 **솔라피 기본 샘플 5건은 삭제 대상**이다. 나머지 7건은 해당 기능이 생기거나 설계가 정리되면 그때 분류한다.

## 6. 정해진 것 / 아직 안 정한 것

### 어미 — ✅ 확정 (2026-08-11): **해요체**

전 메시지 해요체로 통일한다. 층 A·B를 나누지 않는다.

**이유** — 발신 주체가 캐릭터(지똑똑)이기 때문이다. `똑똑!` 다음에 `~되었습니다`가 오면 요정이 공문을 읽는 꼴이 된다. 캐릭터를 쓰기로 한 순간 어미는 따라온다.

```
어색   똑똑! 신청이 완료되었습니다.
채택   똑똑! 신청이 완료됐어요.
```

**돈·환불 문장도 해요체를 유지한다.** 대신 문장을 건조하게 둬서 무게를 만든다. 어미로 격식을 세우지 않는다.

```
똑똑! #{모임명} 자리가 나지 않았어요.

■ 환불 금액: #{결제금액} (전액)

▪ 카드 결제는 카드사 처리에 영업일 3~5일이 걸려요.

다음 모임에서 만나요.
```

> 참고: 토스도 상황과 맥락을 불문하고 모든 문구에 해요체를 적용한다. 일관성 때문이다.

### 지똑똑을 문안에서 어떻게 드러낼지 — ✅ 확정 (2026-08-11)

**메시지를 `똑똑!`으로 연다.** 채널명(지**똑똑**)과 노크 소리가 겹치는 언어유희다.

| 규칙 | |
|---|---|
| **`똑똑!` 다음에 바로 이름과 용건** | `지똑똑입니다`를 붙이지 않는다 — 채널명이 이미 지똑똑이라 반복이다 |
| **전 유형에 붙인다** | 층 A(금액이 나오는 메시지)라고 빼지 않는다. 보내는 사람은 하나인데 어떤 메시지엔 캐릭터가 있고 어떤 데엔 없으면 두 사람이 보내는 것처럼 읽힌다 |

> 용건은 **강조 타이틀**이 맡는다(아래). 그래서 본문 첫 줄은 인사로 써도 된다.

### 강조표기형을 쓴다 — ✅ 확정 (2026-08-12)

카카오 알림톡의 **강조표기형**(`emphasizeType: TEXT`)을 쓴다. 본문 위에 큰 글씨로 **강조 타이틀**과 **부제**가 붙는다.

| | 역할 | 길이 |
|---|---|---|
| **강조 타이틀** | 용건. 이것만 읽어도 무슨 일인지 알아야 한다 | 짧게 (10자 안팎) |
| **강조 부제** | 한 줄 보조. 안심시키거나 다음을 알린다 | 15자 안팎 |
| **본문 첫 줄** | `똑똑! #{회원명}님, …` — 지똑똑의 인사 | |

```
[강조]  자리가 났어요!
[부제]  기다린 보람이 있네요

똑똑! #{회원명}님, 좋은 소식이에요.
```

**타이틀과 본문 첫 줄이 같은 말을 하지 않게 한다**(§3-2). 타이틀은 사실, 본문 첫 줄은 인사다.

### 느낌표 — 조건부 허용 (2026-08-12 개정)

원래 `똑똑!` 하나만 허용했으나, 지똑똑이 활기찬 캐릭터라는 전제가 확정되면서 완화한다.

| 자리 | 느낌표 |
|---|---|
| `똑똑!` | 항상 |
| 좋은 소식의 **강조 타이틀** | 허용 — `자리가 났어요!` `신청 확정!` |
| 인사 문장 | 허용 |
| **아쉬운 소식** (취소·미승격·환불) | **금지** — 돈을 잃은 자리에서 발신자가 신나면 안 된다 |
| **금액·환불·오류 문장** | **금지** |
| 한 메시지에 | **최대 2개** (`똑똑!` + 강조 타이틀). 본문에는 쓰지 않는다 |

### 층 A와 층 B의 어미를 다르게 할지
→ **다르게 하지 않는다.** 위 확정 사항에 흡수됐다.

## 7. 문서 운영

토스는 프린시플을 4개로 시작해 8개까지 늘렸다. 잘 지켜지는 원칙은 없애고 새 원칙을 더하면서.
이 문서도 고정이 아니다. 실제로 메시지를 쓰다가 판단이 안 서는 지점이 생기면 그때 원칙을 추가한다.

**원칙 개수를 먼저 늘리지 않는다.** 지금 7개로 충분하다. 유형을 쪼개는 방식으로 규칙을 늘리지 않는다.

원칙만으로 옳고 그름이 갈리지 않는 경우, 가이드라인으로 한 단계 더 내린다.
예: "잡초를 뽑자"가 원칙이라면, "'혹시'는 잡초다"가 가이드라인이다.
