# 로드맵 인덱스

## 헷갈리는 이유 — 같은 문서가 두 벌이다

파일 7개가 사실상 **두 묶음**이다. 이름이 같고 `-phase3`만 붙어 있어서 어느 쪽을 보는지 헷갈린다.

| | MVP (M1~M6) | Phase 3 (M7~M12) |
|---|---|---|
| 목표 | `milestones.md` | `milestones-phase3.md` |
| 실행 | `work-packages.md` | `work-packages-phase3.md` |
| 검증 | `scenarios.md` | `scenarios-phase3.md` |
| 요구사항 | — | `phase3-requirements.md` |

**Phase 2(알림톡·대기·백오피스)는 로드맵 문서가 없다.** 이 폴더에 안 보인다고 안 한 게 아니라, 문서 없이 진행됐다. 내용은 `CLAUDE.md`에 있다.

## 세 단계가 뜻하는 것

```
마일스톤   목표 — "무엇을 달성하는가"
  └ 워크패키지  실행 — "어떻게 하는가" (완료되면 동작하는 소프트웨어가 나온다)
      └ 시나리오  검증 — "어떻게 확인하는가" (1 시나리오 = 1 행동 = 1 검증)
```

작업을 시작하기 전에 **셋을 다 본다.** 시나리오가 최종 검증 기준이라 이걸 빠뜨리면 완료 판정을 못 한다.

## 지금 어디까지 왔나

- **MVP (M1~M6)** — 완료
- **Phase 2** — 완료 (알림톡·대기 신청·백오피스·Analytics)
- **Phase 3** — M7 Step 1·2·2.5·2.6 완료. 이후로는 **로드맵보다 실제 진행이 앞서 있다**

> ⚠️ **로드맵이 현실과 어긋나 있다.** 2026-07 이후 토론모임 개편·2535 리디자인·전면개편 1단계가 로드맵 순서를 앞질러 진행됐다. M8~M12 문서는 그때 계획대로 남아 있어 **지금 상태를 반영하지 않는다.**
>
> 지금 무엇을 하고 있는지는 `CLAUDE.md`의 Current status와 `memory/project_next_session.md`가 정확하다. **로드맵을 현재 상태의 근거로 쓰지 말 것.**

## 이름 규칙

지금 형식(`<단계>.md` / `<단계>-phase3.md`)을 유지한다. 다음 Phase가 생기면 `-phase4`를 붙인다.

바꾸지 않는 이유 — `CLAUDE.md`와 여러 문서가 이 이름으로 참조하고 있다. 보기 좋게 고치는 대가로 연결이 끊기는 건 손해다.
