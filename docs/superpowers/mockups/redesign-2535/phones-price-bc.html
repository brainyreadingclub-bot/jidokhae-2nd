B · 가격 숨김

목록은 가볍게, 돈은 상세에서
  • 목록이 가장 깔끔 — 카드가 '무슨 책 읽나'에만 집중
  • 불일치 걱정 0 — 가격이 상세에만 있으니 어긋날 일 자체가 없음
  • 할인 체감 늦음 — "반값 이득"을 상세 들어가야 처음 앎
  • 가격 궁금하면 클릭 1회 더

C · 내 금액 표시

정가 그어서 → 내 금액, 카드부터 할인 체감
  • 할인을 목록에서 즉시 체감 — 10,000 그어진 5,000 = "반값!" (단무지님 원한 그림)
  • 카드=상세 항상 일치 — 같은 함수로 계산해 어긋날 수 없음
  • 일반 회원은 그냥 10,000 — 계산·조회 부담 0
  • 목록에 '돈' 신호가 조금 일찍 등장 (균일 소액이라 부담 약함)
정리 — 단무지님이 원한 "처음엔 10,000을 보여주고 5,000임을 알게"는 C안이 정확히 그 그림입니다. 예전에 C를 망설이게 했던 "카드·상세 숫자 불일치" 문제는 같은 계산 함수(getDisplayFee)를 카드에도 쓰면 사라져서, 이제 C는 안전하면서 할인 체감까지 잡습니다. B는 목록이 조금 더 미니멀할 뿐, 할인 매력을 상세까지 미룹니다. 스텝 할인을 '혜택'으로 보이게 하고 싶다면 C, 목록 미니멀리즘이 최우선이면 B.
