## 1. 배경 & 문제

지독해에는 두 종류의 오프라인 모임이 있다.

- **정기모임** — 각자 자기 책을 들고 와 함께 읽는 모임. 평균 10명.
- **토론모임** — 선정된 한 권을 각자 읽어 오고 발제문으로 토론. 월 2회, 참가비 25,000(비회원 30,000), 카페 후기 작성 시 5,000 환급. 평균 3~4명.

토론모임은 세 고통이 겹쳐 참여가 저조하다.

1. **참여율 저조** — 리마인드가 어려워 안 그래도 적은 인원이 더 빠진다.
2. **발제자 구하기 힘듦** — 발제자 한 명이 **책 선정 + 발제문 준비 + 진행**을 모두 떠안는다(보상: 참가비 무료). 부담 집중으로 지원자가 없다.
3. **책 선정이 어렵다** — 무슨 책을 할지 정하는 것 자체가 병목이고, 회원이 흥미 못 느끼면 참여로 안 이어진다.

### 구조적 통찰

세 문제의 뿌리는 하나다 — **"선정자 = 발제자 = 진행자"가 한 사람에게 묶여 있다.** 해법은 **묶음 풀기(unbundling)**, 특히 **책 선정을 회원 투표로 분리**하는 것. 이 하나가 세 문제를 동시에 건드린다: 선정 병목 해소 / 발제자 부담 경감 / 참여 buy-in 상승.

## 2. 개정 핵심 (v2에서 바뀐 방향)

> 전문가 패널(IA·참여설계·비주얼·접근성·운영) 5관점 병렬 리뷰가 독립적으로 **"빅뱅 금지, 조각내라"** 에 수렴. 이후 대화로 확정.

1. **순차 출시** — 5기둥(투표·서재·물어보기·벽·할인)을 한 번에 내지 않는다. 조각으로 쪼개 하나씩 측정.
2. **성공 지표 = 투표자 중 "참석" 전환율** (투표율 아님). 저비용 참여(투표)가 고비용 참여(참석)를 **대체**할 위험(도덕적 면허)이 핵심 리스크.
3. **얼리버드 요금 제거 → 투표적중할인 3%로 대체.** 가격은 병목이 아니고(완독·시간이 병목), 2개월 선점 슬롯 점유 리스크가 있었다. 대신 **이긴 책에 투표한 사람**에게만 할인 → 투표와 참석을 직접 연결(지표 #2를 정면 해결).
4. **"함께 읽은 책 벽" 후순위로 보류** + "벽/책벽" 용어 폐기. 서재에 책이 충분히 쌓인 뒤 재검토.
5. **읽음 ≠ 완독** — 모임 참여는 서재에 "담음"까지만. **완독은 항상 본인 수동.** (토론 참여해도 다 안 읽은 사람 많음 → 자동 완독 금지)

## 3. 핵심 설계 원칙

1. **묶음 풀기(unbundling)** — 선정을 투표로 떼어내 발제자 부담을 줄인다.
2. **한 조각 = 지표 하나** — 조각은 얇게. 한 번에 하나의 북극성 지표만 측정되게.
3. **검증 후 확정** — 미검증 습관/프로세스는 소프트웨어에 못 박지 않는다.
4. **운영자 순부담 0 이하** — 새 반복 작업을 만들지 않는다.
5. **켜고·측정·끄기** — 모든 기능은 플래그 뒤에 격리. 측정 후 안 되면 배포 없이 끈다(§5).

## 5. 켜고·측정·끄는 골격 (신규 기계 없이 기존 3개 재사용)

- **켠다·안내:** `site_settings` 기능 플래그 1개. ON이 되면 첫 노출 때 **닫을 수 있는 얇은 소개 strip**(전면 모달·투어 금지, 250명엔 과함). 유저별 닫힘 기억.
- **측정:** 조각 만들기 **전에** 북극성 지표 1개 + 폐기 기준을 못 박는다. GA4 이벤트는 기존 퍼널 패턴(view/begin/purchase) 복제. 250명이라 admin 미니 카운트(분모=참여자, 분자=응답자)면 충분.
- **끈다·폐기:** 플래그 OFF = 기능 즉시 사라짐, **배포 불필요**(빠른 수정의 핵심). 코드는 처음부터 플래그 뒤에 격리.
- **판단 시점:** 토론모임 월 2회 → 2~4주(4~8 모임 사이클)면 응답률 판단 가능.

## 6. 기능 상세

### 6-0. meeting_type (0조각, 선행)

물어보기·투표적중할인은 **정기/토론 구분**이 데이터에 있어야 동작한다. 현재 `meetings`엔 유형 컬럼이 없다(스키마 확인 완료).

- 컬럼 `meeting_type TEXT NOT NULL DEFAULT 'regular' CHECK (meeting_type IN ('regular','discussion'))`.
- enum(정기/토론). boolean 대신 확장 여지.
- 기존 행은 전부 `'regular'`. 과거 소급 불필요(물어보기는 앞으로의 정기모임만 대상). 다가오는 토론모임만 운영자가 폼에서 유형 지정.
- 운영자 모임 폼(new/edit)에 유형 라디오 1개. `MeetingForm` 단일 진입점.
- **회원 화면 무변경** — 데이터만 심는다. 카드/상세 유형 노출은 1조각 이후.
- **⚠️ [0조각서 제외] 스텝 할인 게이팅:** 지금까지 유형이 없어 "스텝 할인 = 정기모임만" 규칙이 코드로 강제된 적 없다(모든 모임에 50% 걸려옴). 유형이 생기면 정기만 게이팅 가능하나, **회원 결제 금액 변경**이라 별도 회원 배포로 다룬다. 0조각에선 손대지 않고 기록만.

### 6-1. 물어보기 + 서재 (1조각)

회원의 독서를 가볍게 수집하는 개인 공간 + 콜드스타트 해결. **위치 = 마이페이지(/my) 안 섹션(A안).** 하단 탭은 2개(모임 일정·내 신청) 유지 — 탭 수술 0, 플래그 끄면 섹션만 사라짐(완전 되돌리기). 별도 `/library` 페이지는 1조각엔 과함(빈 페이지 이탈) → 서재 충분히 쌓이면 3조각서 C안으로 승격.

> 전문가 5관점(IA·참여설계·비주얼·접근성·운영) 리뷰 + 실제 화면(/my·홈·모임상세) 성장 감사 반영. 아래는 그 결정을 못 박은 것.

**물어보기 (콜드스타트 씨앗):**
- 트리거: **정기모임(`meeting_type='regular'`) 참여 판정**(결제완료 + 모임일 경과, 기존 자동 판정 재사용). **토론모임엔 절대 노출 안 함** — 토론은 이미 책이 정해진 모임이라 "무슨 책 읽으셨어요?"가 모순. 참여 판정 쿼리에 `meeting_type='regular'` 필터 필수.
- 방식: **인라인 strip**(전면 모달 금지). "무슨 책 읽으셨어요?" → 탭하면 그 자리서 도서 검색·선택.
- **한 번에 1건만:** 미응답 정기모임이 여러 건이어도 strip은 **가장 최근 1건만** 노출(잔소리 방지).
- 1조각은 **앱 내 strip만.** 알림톡 유도는 카카오 템플릿 심사 리드타임(수일) 있어 나중 조각.
- 강요 안 함: 닫기(✕) 가능. **모임 1건당 한 번만** — 닫힘·응답을 DB에 기록(별도 dismiss 테이블 or registration 플래그). 닫으면 그 모임 strip 영구 사라짐.
- **문구(확정, 투표 언급 금지):** 제목 "무슨 책 읽으셨어요?" / 보조 "N월 정기모임 · 서재에 기록해두세요". "다음 투표 재료가 돼요" 류 **금지**(§9-11: 안 만든 2조각 기능 미리 약속 금지).

**마이페이지 배치 + 성장 방어 (실제 화면 감사 반영):**
- 섹션 순서: **프로필 → 다가오는 모임 → 물어보기 strip → 내 서재 → 지난 내역(접힘)**. 서재를 지난 내역 **위**에 둔다 — 지난 내역은 장기 회원일수록 무한 성장(1~2년 = 12~24건)해 서재를 아래로 밀어내므로.
- **성장 방어(값싼 것은 첫 구현에 포함, `feedback_defensive_scale_guards`):**
  1. **내 서재는 최근 6권만** 마이페이지에 노출. 그 이상은 "전체 N권 보기" → **같은 화면 인라인 확장**(별도 페이지 X). 확장 그리드도 max-height + 내부 스크롤.
  2. **지난 내역은 기본 접힘**("지난 내역 N건" 헤더). 펼쳐도 **max-height + 내부 스크롤**로 페이지 전체가 무너지지 않게.
  3. 이 방어는 성능이 아니라 **레이아웃 붕괴 예방** 목적 — 소모임(10명·월2회) 규모라 무거운 최적화(가상 스크롤·백엔드 페이지네이션)는 안 함.

**서재 (책 상태 3종):**

| 상태 | 누가 | 자동/수동 | 표시 |
|------|------|----------|------|
| **담음** | 정기 물어보기 답변 / 토론 참여 확정+경과(옵트아웃 가능) | **자동** (완독 아님) | 회색 pill "담음" + **출처 라벨**("N월 정기모임에서" / "직접 검색해서 담음") |
| **완독** | 실제로 다 읽은 본인 | **항상 수동** — 자동 등록 절대 없음 | **초록 아웃라인 pill**(면 아님, "그린은 점" 규율) "✓ 완독" |
| 좋아요 | 본인 | 수동 (3조각) | — |

- 책 담는 "이유"(1조각): **내 독서 기록 + 가벼운 사회 신호("이 책 N명이 담았어요").** 투표 재료라는 더 강한 이유는 2조각에서 소급(안 만든 기능 미리 약속 금지).
- **출처 라벨** 필수 — 자동으로 담긴 책이 왜 여기 있는지 투명하게(참여설계 지적).
- **표지:** 카카오 `thumbnail` URL을 **그대로 참조**(우리가 재호스팅·캐싱 안 함 — 약관 안전). 표지 없으면 **중립 톤 fallback + 제목 텍스트**(색 난사 금지).
- 발견 동선: 1조각은 **[내 서재]만.** [둘러보기]는 3조각.
- **빈 서재 콜드스타트(지금 250명 전원 해당):** 안내형 empty state 필수 — "아직 담은 책이 없어요 / 모임 다녀오시면 '무슨 책 읽으셨어요?'가 떠요. 그때 담으면 여기 쌓여요." (썰렁함·뻘쭘함 방지)

**도서 API = 카카오 책 검색 (2026-07-12 문서·약관 직접 확인 완료):**
- 엔드포인트 `GET https://dapi.kakao.com/v3/search/book`, 인증 헤더 `Authorization: KakaoAK ${REST_API_KEY}`.
- 파라미터: `query`(필수), `target`(title/isbn/publisher/person), `sort`(accuracy/latest), `page`(1~50), `size`(1~50, 기본10). documents 필드: `title` `authors[]` `publisher` `translators[]` `thumbnail` `isbn`(**ISBN10+ISBN13 공백 구분** 문자열) `contents` `url` `datetime` `price` `sale_price` `status`. meta: `total_count` `pageable_count` `is_end`.
- **쿼터:** 일/월 쿼터 방식. 회원 온디맨드 검색 규모라 기본 쿼터로 충분(정확 수치는 앱 발급 후 콘솔 확인).
- **표지 저장 약관:** 문서에 저장/캐싱 금지 명시 없음, "미리보기 크기·화질 변경 가능" 주의만 → **재호스팅하지 않고 thumbnail URL 참조**로 회피.
- **서버 프록시 필수:** REST 키 노출 방지를 위해 클라이언트가 카카오를 직접 부르지 않고 우리 API 라우트(`/api/books/search`)가 대신 호출. 키는 `KAKAO_REST_API_KEY` env(서버 전용).
- **ISBN13 정규화 필수** — 자유 텍스트 금지(판본 파편화가 서재·투표·신호를 깨뜨림). isbn 필드에서 **ISBN13 우선 파싱**, 판형 중복은 정규화 키로 흡수. 검색→선택 방식. 희귀본만 자유입력 fallback(ISBN 없음 플래그).

**측정 (admin 응답률 카운트):**
- 북극성 = **물어보기 응답률**(분모=정기 참여자, 분자=서재 담음). 폐기선 = **4주 내 참여자 30% 미응답 → 방식 재검토**.
- **3상태로 분해**(담음 / strip 봄·안 담음 / strip 닫음) — "안 보여줬나 vs 봤는데 안 했나"를 구분해야 방식을 고칠 수 있음. admin 미니 카운트 화면으로 충분(250명).

**⚠️ 사용자 수동 작업 1개:** 카카오 디벨로퍼스 앱 생성 → REST API 키 발급 → `KAKAO_REST_API_KEY` env 등록. 구현 착수 시 화면 따라 안내.

### 6-2. 책 투표 + 투표적중할인 (2조각)

회원 투표로 다음 토론 책을 정한다.

- **후보 수:** 라운드당 2~3권(기본 3). 상한 3(표 분산 방지), 하한 2.
- **후보 출처:** 서재 **담은 수(인기순) 자동 정렬** → 운영자는 상위에서 **클릭 승인만**(0부터 고르기 아님 = 운영 부담 완화). 자동 개설 아님.
- **투표:** 1인 1표(UNIQUE). 실시간 결과. 홈 노출.
- **확정:** 마감 시 최다득표 1권. 진 책은 다음 라운드 이월. 동점은 담은 수 → 운영자.
- **투표적중할인 3% (얼리버드 대체):**
  - **이긴 책에 투표한 사람**이 그 토론모임 신청 시 **참가비 3% 자동 차감**.
  - **10원 단위 내림**(회원 유리, 참가비 1000단위라 대부분 딱 떨어짐).
  - **스텝 할인 패턴 재사용:** 화이트리스트 `[정가, 정가×0.97]` + RPC `FOR UPDATE` 락에서 "이긴 책 투표자" 자격 재검증(불일치 시 자동 환불).
  - 부정 불가: 투표 마감→집계→결과공개 순서라 "이긴 거 보고 투표" 못 함.
  - 스텝 할인(정기 50%)과는 **다른 모임(토론)이라 중복 자체가 불가.**
  - 프레이밍: "할인"보다 "내가 뽑은 책이 됐어요 · 투표 감사".
- **투표 재진입:** 홈에 "다음 토론책" 상시 요약 카드(배너 사라져도 재진입).

### 6-3. 사회성 (3조각)

- **좋아요** — 닉네임 공개(능동적 공개 의사).
- **읽음(완독) 노출** — 숫자는 공개, 닉네임은 **그 책 완독한 사람끼리만** 상호 공개(250명 소규모라 무제한 노출은 감시 효과 우려 → 상호성으로 완화).
- 실명·지역·아바타 미노출(**기존 명단 정책과 동일**, RPC `get_meeting_participant_nicknames` 선례).
- [둘러보기] 동선 오픈.

## 7. 기술 메모 (개략 — 상세는 조각별 구현 계획에서)

**재사용 (기존 인프라)**
- 모임 생성/조회/카드, 결제(계좌이체 브릿지 + PortOne), 취소/환불 코어
- 알림톡 5종 + 리마인드 크론
- **스텝 할인 가변 요금 패턴**(`pricing.ts`, `staff-slot.ts`, 화이트리스트 + RPC 재검증) → 투표적중할인 차용
- 정기모임 **참여 자동 판정**(결제완료 + 모임일 경과) → 물어보기 트리거
- 참여자 명단 **닉네임-only 정책** → 좋아요/완독자 노출에 동일 적용
- `site_settings` 키-값 → 기능 플래그
- GA4 퍼널 패턴 → 조각별 측정

**신규 (개략)**
- **책** 엔티티 — ISBN13·표지·제목·저자(카카오 도서 API). 담은수/완독수/좋아요 집계
- **서재** — 회원×책 + 상태(담음/완독) + 한줄평(선택)
- **물어보기** — 참여 판정 회원에게 1회 프롬프트(dismiss 상태)
- **좋아요** — 회원×책 (3조각)
- **투표 라운드** — 후보 + 마감일 + 상태 + 이월 (2조각)
- **투표** — 회원×라운드 (1인1표 UNIQUE) (2조각)
- **투표적중할인** — 모임에 연결된 이긴 책 + 투표자 자격 RPC (2조각)

> 정확한 테이블/RPC/RLS/마이그레이션은 **조각별 구현 계획**에서 확정(코드 확정 후 SQL 안내 원칙).

## 9. 확정된 결정 (닫힘)

1. 후기 5,000 환급 → 유지(안 건드림)
2. 순차 출시, 한 조각 = 지표 하나
3. 성공 지표 = 투표자 중 참석 전환율
4. 얼리버드 제거 → 투표적중할인 3%(이긴 책 투표자, 10원 내림, 스텝 패턴 재사용)
5. 벽 → 보류 + 용어 폐기
6. 읽음 ≠ 완독 (담음 자동 / 완독 수동)
7. 물어보기 = 인라인, 1조각은 앱 strip만
8. 도서 API = 카카오 책 검색, ISBN13 정규화
9. 투표 후보 = 서재 인기순 자동정렬 → 운영자 클릭 승인
10. meeting_type 선행(0조각), 스텝 할인 게이팅은 별도 회원 배포
11. **서재 위치 = 마이페이지(/my) 안 섹션(A안).** 별도 페이지/새 탭 X, 플래그 끄면 섹션만 사라짐. `/library` 승격은 3조각(C안)
12. **물어보기 + 자동담음 = `meeting_type='regular'`에만 게이팅.** 토론모임엔 절대 노출 안 함(참여 판정 쿼리에 유형 필터 필수)
13. **성장 방어 첫 구현 포함** — 내 서재 최근 6권 + 인라인 전체보기, 지난 내역 접힘 + max-height 스크롤. 목적 = 레이아웃 붕괴 예방(성능 아님)
14. **표지 = 카카오 thumbnail URL 참조(재호스팅·캐싱 X).** 서버 프록시 `/api/books/search` + `KAKAO_REST_API_KEY`(서버 전용)로 REST 키 은닉
15. **admin 응답률 = 3상태 분해**(담음 / strip 봄·안 담음 / strip 닫음). 북극성=물어보기 응답률, 폐기선=4주 내 30% 미응답
