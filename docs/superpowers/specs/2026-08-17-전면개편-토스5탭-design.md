# 지독해 전면 개편 — 5탭 × 토스 스킨 설계서

> 2026-08-17 · v1
> 이 문서는 2026-08-13~16 세션에서 흩어져 확정된 결정들을 한 곳에 모은 **단일 기준**이다.
> 시각 기준: [토스 18화면 시트](../mockups/2026-08-16-토스-전체-18화면.html) · 결정 원장: `검토문서/DECISIONS.md`

## 0. 한 줄 요약

탭 2개(모임 일정/마이페이지)를 **5개(홈·모임·이야기·서재·나)**로 재편하고,
발제 스레드·번개·인앱 알림을 새로 만들며, 스킨을 **토스 문법 × 지독해 그린**으로 바꾼다.

## 1. 왜 (배경)

- 신규 기능이 생길 때마다 홈에 쌓여 기존 목록을 자르는 구조적 한계 (2026-08-14 진단)
- 앱을 열 이유가 운영 알림뿐 — 사람 알림(답글·공감)이 0종
- 토론모임을 크게 보여줄 자리가 없어 배치 논쟁이 반복됨 → 이야기 탭이 그 자리
- 모임 중에 앱을 쓸 일이 없음 → 모임 자리 발제문 화면이 그 자리

## 2. 정보 구조 (확정)

| 탭 | 답하는 질문 | 내용 |
|---|---|---|
| **홈** | 지금 나 뭐 해야 하지? | 반응(맨 위) → 다음 모임 → 토론 홍보 → 할 일. **목록 금지, 요즘 최대 3줄** |
| **모임** | 언제 어디서 만나나? | 정기(날짜 축 행) · 토론(한 줄) · 번개(가로 카드+열기) |
| **이야기** | 무슨 책, 무슨 말? | 이달의 책+신청 · 발제문 5개+스레드 · 지난 토론 · (3단계) 밑줄 |
| **서재** | 내가 뭘 읽었지? | 물어보기 · 1년 전 오늘 · 담은 책 |
| **나** | 내 기록과 설정 | 카운터 3종 · 연속 참석 · 신청 내역 · 알림함 · 프로필 |

- 토론모임은 **모임 탭=일정 한 줄 / 이야기 탭=본편** 두 곳에 다른 형태로.
- 홈 규칙: **목록을 두지 않는다. 할 일이 없으면 비어 있어도 된다.**
- 계층 규칙: **층마다 옷이 다르다** — 화면당 강조 면 1개, 나머지는 행.
- 탭 5개가 상한. 이후 기능(책 투표·매칭)은 기존 탭 안으로.

## 3. 스킨 (확정 — DECISIONS 2026-08-16)

- TDS 그레이 10단계 그대로: `#191F28 … #F9FAFB`
- 브랜드: `--brand #0FA873` / `--brand-deep #0C8A5F` / `--brand-bg #E8F7F1`
- 경고·긴급: `--warn #FF6B3D` (기존 코럴 #F4552A 대체 여부는 구현 때 병기 검토)
- **테두리 0** — 구분은 회색 면(#F2F4F6)과 여백. radius 14–22. 그림자 최소
- 서체: 산세리프 단일(Pretendard 유지). **Noto Serif KR 회원 화면 퇴장**
- D-day는 큰 숫자("3일"), 금액은 숫자만(원 없음, 기존 정책 유지)

## 4. 새 기능 3종

### 4-1. 발제 스레드 (1단계)
- 운영진이 발제문 N개 등록(번호·소제목·인용·쪽수·질문 — 현행 카톡 형식 그대로)
- **읽기 = 회원 전체 / 답변 쓰기 = 해당 토론 신청자**
- 부담 노출 확정: "8명 중 5명이 답했어요", 미답변 발제 코럴 표시, "살짝 알려주기"
- 답변에 공감·답글. 운영자가 답변에 "모임에서 이어가요" 핀
- **모임 자리 모드**: 당일 발제문 목록에 배너 → 큰 글자 1발제 1화면, 좌우 넘김, 미리 쓴 답변 함께 보기
- 완독 재촉 금지 유지: 진도바·읽는 중 표기 없음 (발제 참여 현황은 허용 — 개정 결정)

### 4-2. 인앱 알림 (1단계)
- **역할 분담**: 알림톡 = 시간 민감(리마인드·승격·환불·물어보기) / 인앱 = 누적(답글·공감·새 번개·발제문 등록·신청 확정)
- 인앱은 카카오 심사 불요 → 먼저 구축
- 진입: 각 탭 상단 벨 + 나 탭 알림 행

### 4-3. 번개 (2단계)
- 회원이 개설: 제목·일시·장소·정원(+한 줄 소개). 결제 없음
- 자격: **정기모임 최근 3개월 내 참여** (자동 상실 — 화면에 마지막 참여일 필수 표기)
- 운영 최소 규칙: 공개 장소만 · 자격자만 열람/개설 · 카드마다 신고 · "못 오면 꼭 알려주세요"
- 노쇼 억제 장치 없음(무료) — 운영 관찰 후 보강

## 5. 단계 (확정)

| 단계 | 내용 | 조건 |
|---|---|---|
| **1** | 탭 5 재편 + 토스 스킨 + 발제 스레드 + 모임 자리 모드 + 인앱 알림 | 즉시. 넷이 상호 의존 |
| **2** | 번개 (개설·참여·자격·신고) | 1단계 안정 후 |
| **3** | 밑줄 (피드 + 서재 책 상세에서 쓰기) | 발제 스레드가 실제로 돌 때만. 자리만 만들고 잠금 |

## 6. 이사 매핑 (기존 → 새)

| 기존 | 새 위치 |
|---|---|
| `/` (홈 전체) | 홈 탭(할 일) + 모임 탭(목록). 캘린더 스트립은 **일단 제거**(날짜 축 행이 대체, 필요시 부활) |
| `/my` 신청 내역 | 나 탭 → 신청 내역 |
| `/my` 프로필 수정 | 나 탭 → 프로필·설정 |
| 서재·물어보기(플래그 OFF) | 서재 탭 |
| `meetings/[id]` 상세·신청·결제 | 모임 탭 하위 — **흐름 로직 무변경, 스킨만** |
| policy/* 공개 페이지 | 유지 (스킨은 후순위) |
| BottomNav 2탭 | 5탭 컴포넌트 교체 |

## 7. DB 초안 (구현 계획에서 확정)

- `discussion_topics` — meeting_id FK, 번호, 소제목, 인용, 쪽수, 질문, 작성자
- `topic_answers` — topic_id FK, user_id, 본문, 핀 여부
- `answer_replies` — answer_id FK, user_id, 본문
- `answer_reactions` — answer_id, user_id UNIQUE
- `app_notifications` — user_id, type, payload(jsonb), read_at
- `flash_meetings` — host_user_id, 제목, 일시, 장소, 정원, 소개, status
- `flash_participants` — flash_id, user_id UNIQUE
- 카운터는 테이블 없이 집계 쿼리(서재=library_entries, 발제=topic_answers, 호스트=flash_meetings)

## 8. 플래그 · 지표 · 폐기선

- 플래그: `site_settings.next_ui` — 새 탭 구조+스킨 전체를 감싼다. OFF면 기존 화면 그대로.
  서재 탭은 `library_enabled`와 **동시에 켠다** (의존성: 서재 켜기 게이트 완료가 선행)
- 북극성(1단계): **발제 답변 작성자 수 / 토론 신청자 수** (모임당). 카톡 시절 답변자 수가 기준선
- 보조: 인앱 알림 열람률, 모임 자리 모드 당일 사용 여부(그날 열람 세션)
- 신뢰 게이트: 토론 3회차. 폐기선: 3회차 평균 답변 참여가 카톡 시절보다 낮으면 스레드 강화 중단하고 원인 조사
