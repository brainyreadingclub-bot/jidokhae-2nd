# 문구 표준 — 신청·결제 화면

> 2026-10-15 대표님 지시로 만든다. **화면 문구는 이 문서를 따른다.** 새 화면·새 문구를 넣을 때 여기서 먼저 찾고, 없으면 여기에 먼저 적는다.
> 상태값·로직·저장 값은 이 문서와 상관없다 — 이 문서는 **사람에게 보이는 글자**만 정한다.
> 알림톡 템플릿 본문은 심사를 받은 것이라 이 문서로 바꾸지 않는다(변수 값도 아래 「알림톡」 참고).

## 1. 신청 상태

| 상태 (저장 값) | 표준 문구 | 쓰는 곳 | 쓰면 안 되는 말 |
|---|---|---|---|
| `confirmed` | **신청 완료** · 지난 모임이면 **참여 완료** | 모임 상세 띠, 신청 내역 배지, 모임 탭 띠, 신청 완료 화면, 운영 화면 신청자 목록 | 신청완료(붙여 씀), 결제완료, 신청한 모임 |
| `pending_transfer` — 회원 화면 | **신청 완료 · 입금 확인 전** | 모임 상세 띠, 신청 내역 배지, 모임 탭 띠 | 확정돼요, 입금 대기, 입금대기, 미입금, 입금 확인 중 |
| `pending_transfer` — 신청 완료 화면 | 제목 **신청됐어요** / 본문 **자리는 잡혀 있어요. 아직 입금 전이라면 아래 계좌로 보내 주세요** | 신청 완료 화면(새·옛) | 입금을 기다리고 있어요, 확인되면 신청이 확정돼요 |
| `pending_transfer` — 운영 화면 | **입금 확인 필요** | 모임 운영 상세 신청자 목록, 정산 탭 | 입금 대기, 입금 확인 대기, 미입금 |
| `waitlisted` | **대기 중** · 대기 신청 직후 화면 제목 **대기 신청이 접수됐어요** | 모임 상세, 신청 내역, 모임 탭 띠, 신청 완료 화면 | 대기 중이에요(배지·띠), 대기 신청 완료, 대기 신청됐어요 |
| `waitlist_cancelled` | **대기 취소됨** | 신청 내역, 운영 화면 | 대기 취소(상태로 쓸 때) |
| `waitlist_refunded` | **대기 종료** + **환불 완료 · N원** | 신청 내역, 운영 화면 | 대기 환불 |
| `cancelled` | **취소됨** · 환불액이 0보다 크면 **환불 완료 · N원** | 신청 내역, 운영 화면 | 환불 N원(「완료」 없이) |
| `cancelled` + `cancel_type = meeting_deleted` | 회원 신청 내역에 **모임이 취소됐어요** | 신청 내역 카드 | — |

- 대기 안내 한 줄: **자리가 나면 자동으로 신청이 완료돼요** / **모임 전날까지 자리가 나지 않으면 결제 금액을 모두 환불해 드려요**
- 계좌이체 신청 단계 버튼 위: **신청하면 바로 자리가 잡혀요. 입금은 안내된 계좌로 해 주세요** — 계좌이체 신청은 누르는 순간 자리가 잡힌다. 「입금이 확인되면 확정」은 틀린 안내다.

## 2. 자리 상태 (정의만 — 구현은 다른 작업이 이 표를 따른다)

| 상황 | 표준 문구 |
|---|---|
| 남은 자리 있음 | **n자리 남았어요** |
| 신청 인원 | **n명이 함께해요** |
| 정원 다 참 | **정원이 찼어요** |
| 신청 기간 끝 | **모집이 마감됐어요** |

쓰면 안 되는 말: 마감되었습니다, 정원이 다 찼어요(→ 정원이 찼어요)

## 3. 버튼

| 동작 | 표준 문구 | 쓰면 안 되는 말 |
|---|---|---|
| 확정·입금 전 신청 취소 | **신청 취소하기** | 취소하기, 신청 취소 |
| 대기 신청 | **대기 신청하기** | — |
| 대기 신청 취소 | **대기 신청 취소하기** | 대기 취소하기, 대기 취소 |
| 계좌이체 신청 | **계좌이체로 신청하기** (0원 모임은 **신청하기**) | 입금 완료 |

## 4. 할인

- **스텝 할인 50%** 하나만 쓴다.
- 쓰면 안 되는 말: 스텝 가격이 적용되었어요, 스텝 가격이 적용되었습니다, 스텝 50%, 스텝½
- 「스텝」은 운영진 역할과 **다른 자격**이다. 「운영진 할인」으로 바꾸지 않는다.

## 5. 결제 수단

- **카드**, **계좌이체** 두 가지만 쓴다.
- 쓰면 안 되는 말: 이체, 카드결제
- 「무료」를 결제 수단처럼 쓰지 않는다. 0원은 **참가비 0원**으로 쓴다.
  - ⏸ 금액 표기 함수(`formatPaidAmount`)가 지금 0원 모임을 「무료」로 쓴다. 이 함수는 홈·알림톡 `#{결제금액}`과 같이 쓰여서 이번 작업에서 바꾸지 않았다(대표님 결정 대기).

## 6. 돈 용어

| 표준 | 뜻 |
|---|---|
| **참가비** | 모임이 정한 값 |
| **결제 금액** | 회원이 실제로 낸(낼) 돈 |
| **환불 예정 금액** | 환불 처리 **전** — 규정으로 계산한 값 |
| **환불 금액** | 환불 처리 **후** |

쓰면 안 되는 말: 돌려받을 금액, 환불할 금액, 결제금액(붙여 씀), 낸 돈

## 7. 「참여」

- 신청 상태에는 쓰지 않는다. 「자동으로 참여가 확정됩니다」 → **자동으로 신청이 완료돼요**
- 「참여 인원」 같은 일반 표현, 지난 모임의 **참여 완료**는 괜찮다.

## 8. 운영하는 사람

- 회원 화면은 **운영진**만 쓴다. 「관리자 페이지에서 보기」 → **운영 화면에서 보기**
- 운영 화면 머리글은 「관리자」 대신 **운영**.
- 역할 배지: admin = **총괄**, editor = **운영진**
- 약관·개인정보처리방침의 「운영자」는 법적 문서라 그대로 둔다.
- 나중에 지역을 붙일 때는 **운영진 · 포항** 형식으로 쓴다(아직 구현하지 않음).

## 9. 말투

| 자리 | 말투 |
|---|---|
| 회원 안내·알림창·오류 | 해요체 (「~했어요」「~해 주세요」) |
| 짧은 상태 배지 | 명사형 (「신청 완료」) |
| 약관·개인정보처리방침 | 합니다체 유지 |
| 환불정책·서비스 소개 | 해요체. 금액·기간·조건은 한 글자도 바꾸지 않는다 |
| 운영 화면 | 짧은 업무체 (「입금 확인 필요 건 없음」「요청 실패」) |
| 서버 메시지 | 회원 화면에 실제로 뜨는 것만 해요체. 개발용 내용(`registrationId가 필요합니다` 같은 것, 결제사 원문)은 화면에 내지 않는다 |

## 10. 알림톡

- 템플릿 본문은 심사를 받은 것이라 바꾸지 않는다.
- 변수 `#{결제상태}`(`lib/registration-status.ts`의 `paymentStatusLabel`: 「입금 확인 중」/「결제완료」)는 이 표준과 다르지만 **그대로 둔다** — 변수 값만 바꿀 때 재심사가 필요 없는지 확실히 확인하지 못했다(2026-10-15).

## 아직 표준과 다른 곳 (다른 작업 담당이라 이번에 안 바꿈)

- 홈 화면(`HomeView`) — 「다가오는 정기모임」 작업
- 발제자 관련(`PresenterPanel`, 모임 상세의 「참석이 어려우면 운영자에게 알려 주세요」) — 발제 작업
- 가입 환영·프로필 입력 — 가입 작업
- 그 밖에 이번 범위 밖: 옛 모임 상세(`MeetingDetailContent`·`MeetingDetailInfo`·`RegistrationStatusBadge`), 이야기 탭 대기 안내(`TalkView`), 나 탭 「운영자 화면」, 모임 삭제 창 「환불할 금액」(`DeleteMeetingButton`), 지역별 매출 안내의 「미입금」(`RegionRevenueTable`)
