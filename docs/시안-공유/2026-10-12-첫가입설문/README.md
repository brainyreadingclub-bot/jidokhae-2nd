## 동의 체크 — 동작 (대표님 지시 반영)

| 상황 | 동의 줄 | 「저장하기」 | 「건너뛰기」 |
|---|---|---|---|
| 아무것도 안 고름 (01·02·10) | **없음** | 꺼짐 | 체크 없이 됨 |
| 하나라도 고름 · 체크 전 (03) | 버튼 위에 나타남 | **꺼짐** | 체크 없이 됨 — 고른 답은 저장하지 않는다 |
| 고름 · 체크 (03b·11) | 체크됨 | 켜짐 | 됨 — 고른 답은 저장하지 않는다 |
| 고른 것을 전부 해제 | 사라지고 체크도 풀린다 | 꺼짐 | 됨 |
| 저장 실패 (04) | 체크 유지 | 「다시 저장하기」 | 됨 |
| 나 탭에서 고치기 (08) | **다시 묻지 않는다** — 처음 저장할 때 이미 동의했다 | 바꾼 게 있을 때만 켜짐 | — |

- 권고대로 **「하나라도 골랐을 때만 체크 필요, 건너뛰기는 체크 없이」**로 정했다. 고르기 전부터 동의 줄을 두면, 아무것도 안 낼 사람에게도 「동의하세요」가 보여 안 내도 되는 일이 해야 하는 일처럼 읽힌다.
- 동의 줄을 스크롤 맨 아래가 아니라 **버튼 바로 위**에 붙였다. 「저장하기」가 꺼진 이유가 바로 위에 보여야 한다 — 맨 아래에 두면 360에서 그 줄을 찾으러 내려가야 한다.
- 문구: 체크 줄 「설문 답 수집·이용에 동의해요 (선택)」 + 「자세히」. 시트(09)는 **모으는 것 · 쓰는 곳 · 보관 · 안 해도 돼요** 네 줄 + 「전체 내용은 개인정보처리방침에 있어요」. 시트 안에서는 동의시키지 않는다(닫기만) — 동의는 체크 줄 한 군데에서만 한다.
- 동의 철회 = 08 「답 모두 지우기」. 지우면 다음에 다시 고를 때 동의 줄이 다시 나온다(가정).
- ⚠️ **확인 필요** — 체크칸 문구·시트 네 줄이 법이 요구하는 알릴 내용을 다 담았는지는 법 확인 대상이다. 시안은 처리방침 수정안(아래)과 같은 말을 쓰도록만 맞췄다.

## 시안이 정한 것

| 정한 것 | 왜 |
|---|---|
| **한 화면에 질문 넷, 순서 = 관심 분야 → 시간 → 알게 된 경로 → 가입 이유** | 「나」에 관한 질문(취향·시간)이 먼저 와야 답하는 재미가 있다. 경로·이유는 운영자 쪽 질문이라 뒤로 |
| **전부 칩 고르기, 자유 입력은 「경로 · 기타」 하나만(20자)** | 경로는 우리가 모르는 새 길을 알려 주는 유일한 질문이다. 이유·분야에 자유 칸을 열면 의미 없는 응답이 돌아오고 처리방침에 적을 범위도 넓어진다 |
| **시간 = 평일/주말 × 오전/오후/저녁 6칸 표, 여러 개** | 결정 문장의 「×」를 그대로 그렸다. 요일과 시간대를 따로 고르게 하면 조합을 알 수 없다 |
| **「저장하기」는 하나라도 고르고 + 동의해야 켜진다** | 위 동의 표 |
| **건너뛰기·저장 둘 다 홈으로, 토스트 한 줄** | 결정대기 「신규 회원 첫 화면에 할 일 하나」(첫 신청)와 자리를 다투지 않게 — 첫 신청까지 늘어나는 건 「건너뛰기」 1번뿐 |
| **설문은 한 번만 보인다** (가정) | 건너뛰거나 저장하면 다시 안 띄운다. 그냥 앱을 닫은 경우도 「한 번 보여 줬다」로 치는 쪽을 권한다 — 다음 방문에 또 뜨면 관문처럼 느껴진다. 구현 방식은 개발·운영이 정한다 |
| **나중에 고치는 곳 = 나 탭 한 줄, 관심 분야·시간만** | 둘은 살다 보면 바뀐다. 경로·이유는 가입 때의 사실이라 고칠 일이 없다. 대신 「답 모두 지우기」는 넷을 다 지운다 |
| 문구 어미 = 지금 5탭 화면 말투(해요체) | ⚠️ `VOICE.md`는 카카오톡 메시지 전용이고 인앱 문구 기준은 어느 문서에도 없다(2026-08-26 결정). 기존 5탭 문구 결만 따랐다 |
| 「답은 운영진만 봐요」 | 모임후기 시안과 같은 말. editor 열람(열린 질문 2)이 「안 됨」으로 정해져도 회원에게 「총괄운영자」는 낯선 말이라 이대로 둔다 |

- **「기타」 응답이 쌓이면 목록을 고친다** — 경로 「기타」에 같은 답이 여러 번 나오면 그 길을 선택지로 올린다.

### B-3. Vercel — 서버가 회원 정보를 거쳐 가는 자리

**확인한 것** — `origin/main` `jidokhae-web/vercel.json`에는 `regions`가 없다(크론 3개뿐). 관리자 전달대로 지금 서버 함수 지역은 **iad1(미국 워싱턴 D.C. 인근)**. 승인 대기 가지 `origin/perf/region-hnd1`의 `vercel.json`에 `"regions": ["hnd1"]`이 들어 있다(2026-10-12 `git show`로 확인) — 반영되면 서버 함수가 **도쿄**에서 돈다.

**왜 이전 항목을 바꿔야 하나** — 지금 Vercel 행의 이전 항목은 「서비스 접속 로그, 쿠키」뿐이다. 그런데 서버 함수(API 라우트·서버 화면)는 프로필 저장·결제 확인·신청 처리를 하면서 **이름·닉네임·전화번호·신청/결제 내역**(앞으로는 가입 설문 응답도)을 받아 처리하고 Supabase로 넘긴다. 저장은 안 하더라도 그 나라 서버를 거쳐 간다. ⚠️ **저장 없이 거쳐 가는 처리도 「국외 이전」으로 적어야 하는지는 법 확인 필요.** 아래는 「적는다」로 볼 때의 문안이다.
