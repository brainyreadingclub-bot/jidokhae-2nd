# 「기타 모임 틀」 설계안 — 외부 검토용

> 작성 2026-10-14 · 설계안이다. 아직 코드나 데이터베이스는 바뀌지 않았다.
> 예시에 나오는 이름·모임·장소는 전부 지어낸 것이다. 실제 회원 정보는 넣지 않았다.

## 지독해는 어떤 곳인가

지독해는 경주·포항·대구에서 2017년부터 이어 온 독서모임이다. 회원은 웹 서비스에서 일정을 보고, 신청하고, 참가비를 낸다(카드 또는 계좌이체). 취소와 환불도 서비스 안에서 처리된다.
모임은 지금 두 종류다. **정기모임**은 지역마다 정해진 요일에 열리고 누구나 신청한다. **토론모임**은 정기모임에 한 번 이상 와 본 회원만 신청하며, 책 한 권과 미리 올라오는 질문(발제)을 놓고 이야기한다.
11월부터 두 가지가 더 생긴다. **한낮의 작업실**은 일요일 오후 네 시간 동안 같은 공간에서 각자 할 일을 하는 모임으로, 한 달에 두세 번 반복된다. **연말파티**는 한 해에 한 번 하는 행사다.
회원 화면은 휴대폰 기준이고 아래 탭이 다섯 개(홈·모임·이야기·서재·나)다. 운영자는 별도 관리 화면에서 모임을 만든다.

## 1. 무엇을 풀려는가

서비스는 모임을 「정기」 아니면 「토론」으로만 안다. 작업실을 정기모임으로 올리면 **정기모임에만 붙어야 할 규칙이 저절로 붙는다.**

| 정기모임에 붙는 규칙 | 작업실·연말파티에 붙으면 안 되는 이유 |
|---|---|
| 스텝(운영을 돕는 회원) 참가비 50% 할인 | 정기모임 운영을 돕는 대가다 |
| 모임 다음 날 「오늘 읽은 책을 서재에 담을까요?」 알림 | 책이 없는 모임이다 |
| 정기모임 참석 1회 = 토론모임 신청 자격 | 작업실에 와도 토론 자격이 생기면 안 된다 |
| 회원 화면 「정기모임」 목록·홈 「가장 가까운 정기모임」 | 정기모임으로 오해한다 |

필요한 것은 **정기 규칙에 끼워 넣지 않고 새 모임을 올리는 틀**이다. 마감은 2026-10-31(첫 작업실은 11월 둘째 주 일요일).

### 범위 밖

- **번개모임** — 회원이 직접 여는 모임이다. 신청이 아니라 「참여」이고 돈이 오가지 않아, 신청·결제·환불 흐름에 올릴 대상이 아니다. 따로 설계한다
- 정기모임 일정 자동 등록 — 별도 작업. 7절에 관계만 적는다

### 예전에 접은 「모임 5종 체계」와 다르다

예전에 회원 등급(멤버십)을 전제로 모임을 이름 다섯 개로 나누는 안을 검토했다가 접었다. 이 틀은 그것을 되살리지 않는다. 종류를 늘리는 조건은 하나다.

> **돈(환불·할인) · 신청 자격 · 알림 중 하나라도 규칙이 다를 때만 종류를 늘린다.** 규칙이 같으면 종류를 만들지 않고 제목으로 구분한다.

## 2. 지금 코드는 어떻게 갈라지나 (전수 조사 요약)

모임 종류를 읽는 자리를 전부 세어 보니 **약 110줄**이고, 그중 실제로 판단하는 곳은 아래와 같다.

| 규칙 | 지금 판정 방식 | 새 종류가 들어오면 | 판정 |
|---|---|---|---|
| 스텝 할인 (화면 계산 + 결제 시 DB 재검증) | 「정기일 때만」 허용 | 할인 안 됨 | 맞음 |
| 책 담기 알림 | 「정기일 때만」 | 안 나감 | 맞음 |
| 토론 자격으로 세기 | 「정기일 때만」 셈 | 안 셈 | 맞음 |
| 토론 자격 검사 | 「토론일 때만」 검사 | 누구나 신청 | 맞음 |
| 환불 비율 | 토론이면 14일/7일, **그 외 전부** 정기 규칙(3일 전 100% · 2일 전 50% · 그 뒤 0%) | 정기 규칙 | 결정 필요 |
| 정원 3명 미만이면 인원 숫자 가리기 · 0원 모임 처리 · 대기 신청과 자동 승격 · 전날 알림 | 종류 무관 | 같게 적용 | 맞음 |
| **모임 탭 「정기모임」 목록** | 「토론이 아니면 정기」 | **정기 목록에 섞인다** | 고쳐야 함 |
| **홈 「가장 가까운 모임」** | 「토론이 아니면 정기」 | **작업실을 정기 자리에서 권한다** | 고쳐야 함 |
| **모임 상세 머리 이름 · 운영자 화면 이름** | 「토론이 아니면 정기」 | **「정기모임」으로 나온다** | 고쳐야 함 |
| **운영자 모임 만들기** | 선택지 두 개 | **만들 수 없다** | 고쳐야 함 |
| 지역별 매출 · 공간 대여비 정산 | 종류 무관, 지역·공간으로 합산 | 같은 공간이면 합쳐짐 | 결정 필요 |

**핵심:** 돈과 자격 규칙은 이미 「정기일 때만」 쪽으로 짜여 있어서 새 종류를 저절로 뺀다. 틀리게 나오는 곳은 전부 **화면과 운영자 폼**이다. 그래서 돈을 다루는 코드는 건드리지 않고 마감 안에 끝낼 수 있다.

## 3. 데이터 모양 — 세 안

| | A안 · 종류 값 추가 + 규칙표 한 곳 | B안 · 「기타」 하나 + 모임마다 규칙 칸 | C안 · 종류를 데이터베이스 표로 |
|---|---|---|---|
| 모양 | 모임 종류에 「작업실」·「행사」 두 값을 더한다. 종류별 규칙은 코드 안 표 하나에 모은다 | 종류는 「기타」 하나. 모임마다 환불 방식·할인 여부·자격 칸을 채운다 | 「종류」 표에 한 줄 = 규칙 한 묶음. 모임은 그 줄을 가리킨다 |
| 새 종류 추가 | 코드 수정 + 배포 한 번 | 배포 없이 모임 만들 때 칸 채움 | 배포 없이 표에 한 줄 |
| 돈 규칙을 바꿀 수 있는 사람 | 코드 검토를 거친 사람만 | **모임을 만드는 운영진 누구나** (할인·환불을 모임마다 켤 수 있다) | 표를 쓸 권한이 있는 사람 |
| 결제·신청 DB 함수 | 그대로 (이미 새 값을 막는다) | 새 칸을 읽도록 다시 써야 한다 | 표를 읽도록 다시 써야 한다 |
| 「5종 체계」가 다시 생길 위험 | 낮음 — 종류 하나 = 검토 한 번 | 중간 — 규칙 조합이 흩어진다 | **높음** — 이름만 다른 종류를 배포 없이 계속 늘릴 수 있다 |
| 10/31 안에 | 된다 (DB 변경은 허용 값 목록 한 줄) | 빠듯 | 빠듯 |

**권고: A안.** 지금 잘 막고 있는 돈 함수를 마감에 맞춰 고치는 것이 가장 비싼 위험이다. B·C는 그걸 강요한다. 규칙이 다른 종류가 한 해에 셋 이상 새로 생기면 그때 C로 옮긴다.

A안의 규칙표 (초안):

| 종류 | 화면 이름 | 환불 | 스텝 할인 | 정기 참석으로 세나 | 모임 탭 자리 |
|---|---|---|---|---|---|
| 정기 | 정기모임 | 3일/2일 | 있음 | 예 | 정기 |
| 토론 | 토론모임 | 14일/7일 | 없음 | 아니오 | 토론 |
| 작업실 | 작업실 | 결정 필요 (권고 3일/2일) | 없음 | 아니오 | 그 밖의 모임 |
| 행사 | 행사 | 결정 필요 (권고 3일/2일) | 없음 | 아니오 | 그 밖의 모임 |

규칙표에 없는 값이 들어오면, 환불만 옛 데이터처럼 정기 규칙을 따르고 할인·자격은 주지 않는다. 모르는 값에 혜택을 주지 않는다.

DB 변경 초안 (실행하지 않았다):

```sql
ALTER TABLE meetings DROP CONSTRAINT IF EXISTS meetings_meeting_type_check;
ALTER TABLE meetings ADD CONSTRAINT meetings_meeting_type_check
  CHECK (meeting_type IN ('regular', 'discussion', 'workshop', 'event'));
```

## 4. 화면에서 어디에 보이나

시안 그림은 `시안/` 폴더에 있다(가상 데이터, 휴대폰 390px 폭).

| 화면 | 바뀌는 것 |
|---|---|
| **모임 탭** | 정기모임(날짜 줄) · 토론모임(책 표지 카드) 아래에 **「그 밖의 모임」 구역**이 생긴다. 정기 줄 모양을 빌리지 않는다 — 종류는 이름표가 아니라 생김새로 구분한다는 기존 원칙. 해당 모임이 없으면 구역째 숨긴다 |
| **모임 상세** | 정기모임과 같은 상세 틀(소개글·환불 안내·신청 버튼). 머리 이름만 「작업실」 등 종류 이름 |
| 신청·결제·취소 | 정기모임과 같다 |
| 홈 | 따로 칸을 만들지 않는다. 신청했으면 「내 모임」 카드에 뜬다 |
| 이야기·서재 탭 | 없음 (책과 발제가 없는 모임) |
| **운영자 모임 만들기** | 종류 선택지 2개 → 4개 (정기모임 · 토론모임 · 작업실 · 행사) |

탭은 다섯 개 그대로다. 새 탭을 만들지 않는다.

시안 그림 (가상 데이터 — 장소는 「가상 공간 A/B/C」, 연말파티 날짜·참가비도 지어낸 값):

| 파일 | 내용 |
|---|---|
| `시안/01-모임탭-비교.png` | 모임 탭 지금 / 바뀐 뒤 나란히 |
| `시안/02-모임탭-전.png` · `03-모임탭-후.png` | 같은 것을 한 장씩 |
| `시안/04-작업실-상세.png` | 작업실 상세 — 머리 이름 「작업실」, 끝 시각까지 표시 |
| `시안/05-운영자-폼-전.png` · `06-운영자-폼-후.png` | 운영자 모임 만들기 — 종류 선택지 2개 → 4개 |

시안에서 정한 생김새:
- 「그 밖의 모임」은 회색 면 카드에 **제목이 얼굴**이다. 정기(날짜 줄)·토론(표지 카드) 모양을 빌리지 않는다
- **반복 모임(작업실)** 은 제목 → 주기 줄 → 장소·참가비 → 회차 날짜 알약(「8일 · 3자리 남음」「29일 · 마감」, 누르면 그 회차로). **한 번짜리(행사)** 는 날짜 줄이 맨 위이고 알약이 없다. 알약이 있고 없음으로 둘이 갈린다
- 주기 표기는 「2·4·5주 일요일 · 오후 1–5시」(격주가 아니다)

시안이 드러낸 빈칸 둘: ① 모임 데이터에 **끝나는 시각 칸이 없다**(작업실 「1–5시」·상세 끝 시각을 그리려면 필요) ② **주기 줄**(「2·4·5주 일요일」)을 담을 곳이 없다 — 운영자가 손으로 쓰는 칸으로 둘지, 종류 규칙표에 둘지

|---|---|---|
| 제목 | 한낮의 작업실 | 2026 연말파티 |
| 지역 · 장소 | 포항 · 가상 공간 A | 미정 |

작업실에만 전용 알림이 두 개 생긴다 — **시작 전 안내**, **끝나기 전 뒷정리 안내**(에어컨·조명). 카카오 알림톡은 새 문구마다 사전 심사가 필요해서, 이 심사가 일정에서 가장 오래 걸린다. 심사가 늦으면 기존 「전날 알림」만으로 운영하고 뒷정리는 현장에서 안내한다. 작업실 신청자는 같은 모임에 대해 최대 세 통(전날 · 시작 전 · 뒷정리)을 받는다.

## 7. 정기모임 자동 등록과의 관계

자동 등록은 「공개 전 초안」 상태가 필요하다. 그것은 모임의 **공개 상태** 문제이지 **종류** 문제가 아니다. 초안을 종류 값으로 표현하지 않는다(종류를 읽는 자리들이 초안을 공개 모임으로 읽게 된다). 둘은 따로 나가고, 같은 운영자 폼을 건드리므로 이 틀이 먼저 들어간다.

## 검토받고 싶은 질문

**질문 1. 데이터 모양 — A안(종류 값 추가 + 코드 안 규칙표)으로 충분한가?**
- 선택지: A안 / B안(모임마다 규칙 칸) / C안(종류를 DB 표로)
- 권고: **A안.** 돈·자격 규칙이 이미 「정기일 때만」으로 짜여 있어 결제 함수를 안 고쳐도 되고, 운영진이 모임마다 할인·환불을 켜는 길이 생기지 않는다. 우리가 놓친 A안의 약점이 있는지 봐 달라.

**질문 2. 「규칙이 다를 때만 종류를 늘리고, 한 번짜리는 전부 『행사』 하나에 담는다」는 기준이 맞는가?**
- 선택지: (가) 이 기준 그대로 / (나) 행사도 성격별로 미리 나눈다(파티 · 강연 · 야외 등) / (다) 작업실도 「행사」에 넣고 종류를 하나만 더한다
- 권고: **(가).** (나)는 이름만 다른 종류가 늘어나 예전에 접은 분류로 돌아간다. (다)는 작업실에만 있는 전용 알림 두 개를 고르는 기준이 사라진다.

**질문 3. 모임 탭에서 작업실·행사를 「그 밖의 모임」 구역 하나로 묶어 정기·토론 아래에 두는 배치가 맞는가?**
- 선택지: (가) 아래 구역 하나 / (나) 정기모임 날짜 줄에 섞되 생김새만 다르게 / (다) 모임 탭 위쪽에 「정기 · 토론 · 그 밖」 고르기 버튼
- 권고: **(가).** 정기모임이 신청의 대부분이라 맨 위를 지킨다. (나)는 날짜 순으로 섞여 정기모임으로 오해하기 쉽다. (다)는 고르지 않으면 안 보여서 작업실을 처음 아는 사람이 놓친다. 시안 `시안/01-모임탭-비교.png`를 보고 판단해 달라.
