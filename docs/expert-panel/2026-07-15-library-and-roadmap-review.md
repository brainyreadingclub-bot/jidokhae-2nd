# Expert Panel: 내 서재 + 이후 기능(물어보기·투표·사회신호) 본질 검토
> 2026-07-15 | 패널 7명

## 질문
JIDOKHAE(지독해, 회원 250명) "내 서재(My Library)" 기능과 그 이후 추가될 기능(물어보기·투표·투표적중할인·사회신호)의 본질적 부분을 7개 역할(PM·UX·시니어개발·데이터분석·PMM·QA·테크라이터/CX) 전원 관점에서 검토. 현재 상황 = 1조각(서재+물어보기) prod dark 배포 완료(플래그 OFF, 회원 노출 0), 다음 = 플래그 켜기 전 회원 콜드스타트 검증 → 2조각(투표+할인) → 3조각(사회신호).

## 라운드 1: 독립 의견 (요지)

### 📊 조우선 (PM)
- **주장:** North Star가 뒤바뀜. 서재는 2조각 투표의 재료 공급 수단이라는 본질을 인정하고, 1조각 폐기선을 **응답률 + 투표 가능 최소 카탈로그 절대량(고유 책 N권·응답자 M명)**으로 이원화해야.
- **리스크:** 4주 30% 폐기선은 분모가 한 자릿수라 노이즈. 응답률만 좋고 카탈로그는 빈약한 "허영 지표 통과" 위험.
- **행동:** 폐기선 이원화 + 4주는 1차 체크포인트, 실판정은 6~8주(4모임 사이클).

### 🎨 한결 (UX)
- **주장:** 콜드스타트 문제의 본질은 요소 개수가 아니라 **같은 의미("서재에 책 담아라")를 IntroStrip·empty·AskStrip 3개가 반복.** IntroStrip 제거/흡수, empty는 문구 최소화, "책 담기" CTA 단일 소유자.
- **발견:** empty에서 검색창(`+ 책 검색해서 담기`)이 신규 회원 첫 액션으로 뜸 — 멘탈모델(서재=참여하면 자동으로 차는 곳)과 반대.
- **행동:** 콜드스타트 3분기(①미참여+빈서재 ②참여+빈서재 ③책있음) 목업 렌더로 겹침 0 눈으로 검증 후 플래그 ON.

### 🏗️ 남기표 (시니어 개발)
- **주장:** 1조각 격리·멱등·ISBN13 정규화는 견고(플래그 OFF면 쿼리·번들 오염 0, `books.isbn13 UNIQUE` + `library_entries UNIQUE(user,book)` + 23505→already). 그러나 미래 부채 3개.
- **부채:** (1) 카카오 thumbnail은 CDN URL이라 **절판/판올림 시 만료·깨짐** — fallback이 `null`만 커버, 죽은 URL 미커버. (2) 책별 담은수/완독수 **집계 뷰/RPC 없음** — 2조각 투표 후보 인기순 정렬에 필요, 성장 시 full scan 부담. (3) 3조각 완독자 **닉네임 상호노출**은 현 RLS로 불가 → 전용 SECURITY DEFINER RPC 필요, RLS 넓히면 안 됨.
- **행동:** 2조각 전 집계 RPC 정의 + 완독자 상호노출 전용 RPC(search_path='') + 표지 `<img onError>` 폴백.

### 📈 수치 (데이터)
- **주장:** 1조각 응답률은 표본 충분(60일 윈도우 ≈ 40 참여-건, 70% vs 30% 방향 판별 가능). 반면 **2조각 "투표자 참석 전환율"은 selection bias로 인과 증명 불가** — 여기가 진짜 위험.
- **리스크:** 열성 회원이 투표도 참석도 함(교란변수) → 상관을 할인 효과로 오독. 도덕적 면허(대체 효과)는 투표자 참석률만 봐선 감지 불가, **도입 전후 전체 참석 인원 절대 변화**를 봐야.
- **행동:** 1조각 폐기 판정을 4주 달력 → **분모 n≥30 표본 기준**. 2조각은 할인/비할인 라운드 번갈이(준실험 A/B) + 총참석자 시계열.

### 📣 마케터 배 (PMM)
- **주장:** 문구가 운영자 언어("기록 쌓기")에 머묾. 콜드스타트에서 **즉각적 회원 혜택이 비어 있음.** "N명이 담았어요" 사회신호는 스펙엔 있으나 코드엔 없고, 있어도 N=0~1에선 독(역-사회신호).
- **근거:** IntroStrip·empty 둘 다 "미래의 축적"만 약속하는 같은 말. AskStrip(모임 직후 온기)만 진짜 전환 트리거. "내 독서 기록"은 회원 혜택이 아니라 운영자의 데이터 수집 — 회고/정체성 프레임("올해 내가 읽은 책")으로 번역해야.
- **행동:** 소개 strip을 회고/정체성 문구로 차별화, 사회신호는 임계(3명↑) 전 비노출 확정, 전환은 AskStrip에 집중.

### 🛡️ 문지기 (QA)
- **주장:** 플래그 ON 직전 최우선 = **응답률 통계(`getAskStats`) 왜곡** + 카카오 API 실패 경로 UX 미검증.
- **버그:** `getAskStats` 분자에 60일 윈도우 필터 미적용 → 윈도우 넘긴 answered 누적 시 **responseRate 100% 초과 가능**(분모5·answered6→120%). 운영 지표 신뢰 붕괴.
- **엣지:** 담은 뒤 서재에서 삭제하면 "실제 담긴 책 0권인데 answered=1". dismiss 후 모임 취소→재신청해도 strip 안 뜸(명세 부재). 카카오 쿼터초과/타임아웃 시 첫 담기 조용히 실패 가능.
- **행동:** 플래그 ON 전 (a) getAskStats 윈도우 회귀 테스트 1건 (b) 신규 계정으로 검색 타임아웃/빈결과/ISBN없는 외서 3케이스 preview 검증. 2조각 할인은 화이트리스트·마감경계·중복투표를 설계 단계에서 시나리오 선고정.

### ✍️ 나풀어 (테크라이터/CX)
- **주장:** 실제 혼란은 "담음vs완독"이 아니라 **코드에 실제로 뜨는 "읽는 중vs완독"**(스펙-코드 불일치)과 자동으로 책이 꽂히는 순간.
- **발견:** 코드 pill = "읽는 중/✓완독"(`LibraryGrid.tsx:159`), 스펙 = "담음/완독". empty = "모임에서 읽은 책이 여기 쌓여요"(스펙과 미묘히 다름). 출처 라벨은 자동 담김(`source==='ask'`)에만 붙고 **검색 담김엔 라벨 없음**(스펙의 "직접 검색해서 담음" 누락).
- **리스크:** 자동으로 꽂힌 책이 "읽는 중"으로 뜨면 다 읽고 온 회원이 "왜 읽는 중이지?" 망설임. 중장년 회원은 "누가 내 기록 건드렸나" 오해 — 출처 라벨이 유일 방어선인데 절반만 붙음.
- **행동:** pill을 스펙대로 "담음"으로 통일, 검색 담김에도 "직접 담음" 라벨, 소개 strip=새 기능 역할·empty=지금 뭘 하면 되는지 역할로 분리, 카톡 공지 1줄이면 충분(온보딩 투어 불필요).

## 라운드 2: 토론

### 상호 반박 & 보강
- **한결 🎨 ↔ 마케터 배 📣 ↔ 나풀어 ✍️ (문구 3중 중복)**: 3명이 독립적으로 같은 결론에 수렴 — IntroStrip·empty·AskStrip이 같은 말을 반복. 강한 신호. 나풀어가 "역할 분리"(소개=새 기능/empty=지금 할 일)로, 마케터 배가 "회고/정체성 프레임"으로, 한결이 "CTA 단일 소유자 + 3분기 목업"으로 각각 해법을 보태 상호 보강. 반박 없음.
- **조우선 📊 ↔ 마케터 배 📣 (서재의 본질)**: 대립. 조우선은 "서재 = 투표 재료 수단, 자체 가치 약함". 마케터 배는 "회고/정체성으로 자체 회원 혜택 성립 가능". → 실행상 수렴: 문구는 회고 프레임(마케터 배)으로 세우되, 1조각 **성공 판정에는 카탈로그 절대량 포함**(조우선). 즉 회원에게는 회고, 우리에게는 카탈로그 — 두 목적을 분리 관리.
- **수치 📈 ↔ 조우선 📊 (폐기선)**: 강하게 동의·보강. 둘 다 "4주 달력 기준은 위험". 수치가 "분모 n≥30 표본 기준"으로 정량화, 조우선이 "이원화(응답률+카탈로그)"로 축을 추가. 결합하면 "표본 n≥30 도달 시 응답률+카탈로그 절대량 동시 판정".
- **수치 📈 ↔ (2조각 전원)**: 수치가 2조각 "투표자 참석 전환율"의 인과 오독 위험을 가장 강하게 경고. 남기표(집계 RPC 선행)·문지기(투표 엣지 선고정)가 기술적으로 뒷받침 → 2조각은 착수 전 측정 설계(A/B 라운드 + 총참석자 시계열)를 먼저 못박아야 한다는 데 이견 없음.
- **문지기 🛡️ ↔ 나풀어 ✍️ (스펙-코드 drift)**: 서로 다른 drift를 발견(문지기=getAskStats 버그, 나풀어=pill 문구·라벨 누락). 둘 다 "코드가 스펙과 다르게 나갔다"는 동일 근본 문제의 증상. 플래그 ON 전 코드-스펙 재정합이 필수라는 결론 강화.
- **남기표 🏗️ ↔ 마케터 배 📣 (사회신호)**: 동의. 마케터 배는 "N=0~1이면 독", 남기표는 "집계 RPC 자체가 없음". → 사회신호는 1조각에서 미구현 유지 + 3조각에서 임계(3명↑) + 전용 집계로 도입.

### 핵심 논쟁점
1. **서재의 본질**: 투표 재료 수단인가(PM) vs 자체 회원 혜택 성립인가(PMM). → 회원 대면=회고 프레임, 내부 판정=카탈로그 절대량으로 분리 관리하며 실행 수렴.
2. **폐기선 기준**: 4주 달력(현행 스펙) vs 표본 n≥30 + 이원화(PM·데이터). → 후자로 개정 합의.
3. **사회신호 도입 시점**: 1조각(스펙 언급) vs 3조각+임계(PMM·개발). → 3조각+임계로 합의.

### 최종 합의
플래그를 켜기 전에 **"콜드스타트 화면"과 "코드-스펙 정합"을 먼저 고쳐야 한다**는 데 7명 전원이 수렴한다. 구체적으로 (1) IntroStrip·empty·AskStrip의 문구 3중 중복을 역할 분리로 해소하고 3분기 목업을 렌더 검증, (2) pill "읽는 중"→"담음" 스펙 통일 + 검색 담김 출처 라벨 보강, (3) `getAskStats`의 responseRate 100% 초과 버그를 윈도우 필터 + 회귀 테스트로 수정, (4) 신규 계정으로 카카오 검색 실패 3케이스를 실제 검증한다. 측정 설계는 4주 달력에서 **표본 n≥30 기준 + (응답률 ∧ 최소 카탈로그 절대량) 이원 폐기선**으로 개정한다. 서재는 회원에겐 회고/정체성으로 프레이밍하되 전략적 목적(투표 카탈로그)은 내부 지표로 별도 관리한다. 2조각 투표적중할인은 **selection bias·도덕적 면허를 분리 감지하는 준실험(할인/비할인 라운드 번갈이 + 도입 전후 총참석자 시계열)** 설계를 착수 전 못박고, 3조각 사회신호는 임계(3명↑) + 전용 SECURITY DEFINER RPC로 미룬다.

## 액션 아이템
**A. 플래그 ON 전 (필수 게이트)**
1. [코드/QA] `getAskStats` 분자에 60일 윈도우 필터 적용 → responseRate 100% 초과 버그 수정 + 회귀 테스트 1건.
2. [코드/CX] pill "읽는 중"→"담음" 스펙대로 통일(`LibraryGrid.tsx`). 검색으로 담은 책에도 출처 라벨("직접 담음") 부여.
3. [UX/문구] IntroStrip·empty·AskStrip 문구 3중 중복 제거 — 역할 분리(소개=새 기능 / empty=지금 할 일 / AskStrip=모임 직후 CTA 단일 소유). 콜드스타트 3분기(①미참여+빈서재 ②참여+빈서재 ③책있음) 목업 렌더로 겹침 0 검증.
4. [QA] 신규(빈 서재) 계정으로 카카오 검색 타임아웃·빈결과·ISBN없는 외서 3케이스 preview 육안 검증 + BookSearchInput 에러 피드백 확인.

**B. 측정 설계 개정 (플래그 ON과 함께)**
5. [PM/데이터] 1조각 폐기선을 "4주 30%" → **분모 n≥30 도달 시 판정 + (응답률 ∧ 2조각 착수 최소 카탈로그: 고유 책 N권·응답자 M명)** 이원화. 4주는 1차 체크포인트.
6. [PMM] 소개 strip을 회고/정체성 문구로 차별화. 사회신호("N명이 담았어요")는 1조각 미구현 유지 + 임계 3명↑ 전 비노출로 확정.

**C. 2·3조각 착수 전 선설계**
7. [시니어개발] 책별 담은수/완독수 집계 뷰 또는 `get_book_stats()` RPC 정의(2조각 투표 후보 인기순). 3조각 완독자 상호노출은 전용 SECURITY DEFINER RPC(search_path='')로 격리. 표지 `<img onError>` 폴백 추가.
8. [데이터/QA] 2조각 투표적중할인 = 할인/비할인 라운드 번갈이(준실험) + 도입 전후 총참석자 시계열. 화이트리스트·마감경계·중복투표·이긴책 자격 경계값을 설계 시나리오로 선고정.

## 미합의 사항
- **서재의 본질적 가치**(자체 유틸리티 vs 투표 수단): PM(수단론)과 PMM(회고/정체성 자체가치)이 끝까지 완전 합의하지 않음. 단 실행 차원("회원=회고 프레임, 내부=카탈로그 지표")에서는 수렴. 이 프레이밍이 실제로 첫 담기를 이끄는지는 플래그 ON 후 데이터로만 판가름.
