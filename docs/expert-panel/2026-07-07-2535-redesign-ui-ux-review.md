# Expert Panel: 지독해 2535 리디자인 시안 UI/UX 평가
> 2026-07-07 | 패널 3명

## 질문
지독해(독서모임 웹서비스, 타겟 2535) 리디자인 시안을 디자인 전문가 관점에서 평가. 유력안 A안 v2 "모던 잉크 그린"(#127A5A 앵커 + 오프화이트/웜그레이 뉴트럴 + 에디토리얼 세리프 제목 + Pretendard 본문, 앵커색은 CTA/활성날짜/가격 '점'에만)이 정말 2535를 끌어들일 완성도인지, 약점은 뭔지, 로고/브랜드 확장 시 문제는 없는지. 대상 시안: `phones-reskin.html`(실화면 적용 비교), `phones-missing.html`(빠진 화면/상태 6종), `phones-9.html`(A안 v2 원본), 디자인 문서.

## 라운드 1: 독립 의견

### 🎨 정아름 (브랜드/아트 디렉터)
- **핵심 주장:** 방향은 프리미엄·2535 준비 완료. reskin(②)이 원본 A안(③)을 넘어선다.
- **근거:** 앵커 1색을 점으로 쓰는 절제가 토스/당근 정석과 일치. 세리프 제목이 '읽는 서비스' 정체성을 시각화. reskin이 실화면에 적용돼 설득력이 원본보다 높다.
- **리스크:** grain opacity .3~.5는 '오래된 종이'로 읽혀 올드해질 수 있음 → ≤.2 상한. phones-9에 §7 반려안(초록 세리프 ₩가격, 이모지 태그)이 살아있음.
- **추천 행동:** phones-9의 세리프 가격·이모지 태그 제거, grain ≤.2로 고정.

### 🧭 한결 (프로덕트 디자이너/UX)
- **핵심 주장:** 카드 인라인 CTA가 "목록=훑기, 상세=결정" 원칙과 충돌 — 액션 가능 상태만 버튼, 나머지는 태그.
- **근거:** 마감/신청완료/입금대기까지 버튼이면 초록이 면화. "신청하기" 버튼이 상세로 이동하면 결제 기대와 불일치. 입금대기 "신청 완료"는 "입금해야 확정"과 모순.
- **리스크:** 카드에 가격 노출 시 스텝 할인가(카드 정가 vs 상세 50%)·마스킹(3명 미만) 로직과 정합성 회귀. 빠진 상세 화면에 전환 신호 부족.
- **추천 행동:** 카드 CTA 상태 분기 + 입금대기 "신청 접수됨 + 입금 기한"으로 카피 수정.

### 📐 도규범 (디자인 시스템/접근성, 반대 관점)
- **핵심 주장:** mute 토큰이 두 값(#6B7684/#8B95A1)으로 갈라진 채라 "완성"이라 부를 수 없음.
- **근거:** 문서는 #6B7684인데 시안은 소형 텍스트(`.time` 11.5px, `.day .dl` 10px, `.paynote`/`.stickynote` 11px)에 #8B95A1(대비 2.9:1, AA 실패) 사용. phones-9 L71 초록 세리프 `₩10,000`은 §3(무채색/Pretendard/단위없음) 위반이자 §7 반려안이 원본에 잔존.
- **리스크:** 프리미엄 인상이 소형 텍스트 대비 붕괴로 '싼' 인상으로 역전.
- **추천 행동:** §6에 "mute=#6B7684 단일, #8B95A1는 ≥12px/아이콘만" 못박고 시안·원본 일괄 교체.

## 라운드 2: 토론

### 상호 반박 & 보강

**🎨 정아름:**
- 한결에게: 카드 CTA 태그 강등은 절반 동의 — "모집중=초록 버튼 / 마감=회색 태그" 대비가 오히려 앵커를 더 튀게 함. 단 액션 불가 상태까지 버튼이면 초록 면화 지적은 맞음.
- 도규범에게: 전적 동의. #8B95A1 잔존은 실수. phones-9 초록 세리프 가격도 즉시 제거.

**🧭 한결:**
- 정아름에게: grain ≤.2 동의. 단 브랜드 완성도보다 "카드가 무엇을 약속하는가"가 먼저 — 상세로 가는 버튼은 결제 약속처럼 읽히면 안 됨.
- 도규범에게: 접근성 지지 + 스텝 할인가·마스킹 로직은 접근성뿐 아니라 데이터 정합성 회귀 리스크.

**📐 도규범:**
- 정아름에게: "reskin>원본" 동의하나 토큰이 갈라진 채라 "완성" 명명은 위험. 토큰 단일화 후 완성도 논의.
- 한결에게: 카드 CTA 분기 찬성. "입금대기=신청 완료"는 거짓 정보 — 신뢰성 문제. "신청 접수됨 + 입금 기한"으로.

### 핵심 논쟁점
1. **카드 인라인 CTA 범위** — 정아름(대비 효과로 유지)↔한결(액션 가능만 버튼). 사용자가 "무조건 하자"로 확정 → 폐지 논외, 범위 조정으로 수렴.
2. **"완성도" 판단 시점** — 정아름(시안으로 검증됨)↔도규범(토큰 단일화 전 판단 불가). 근거 품질 도규범 우세.
3. **가격/CTA 카드 노출의 2차 파급** — 한결 단독 제기, 반박 없음 → 합의 승격.

## 최종 합의
방향(잉크그린 앵커 + 절제 뉴트럴 + 에디토리얼 세리프)은 2535를 끌어들일 완성도가 맞고 reskin(②)이 원본 A안(③)보다 낫다. 단 "완성" 전 3개 필수 보정:
1. **토큰 정합성** — mute를 #6B7684 단일 토큰으로 고정, #8B95A1는 ≥12px/아이콘 stroke만. 시안·phones-9 즉시 교체.
2. **카드 CTA는 폐지가 아닌 상태 분기** — 액션 가능(모집중→`신청하기`, 대기가능→`대기 신청`)만 버튼, 액션 불가(마감·신청완료·입금대기)는 태그로 초록 면적 억제. 버튼은 상세 이동이므로 결제를 약속하지 않게.
3. **입금대기 카피** — "신청 완료"(거짓)→"신청 접수됨 + 입금 기한".
추가로 카드 가격/CTA 노출 시 스텝 할인가·3명 미만 마스킹 로직과의 정합성을 코드 마이그레이션 계획에 리스크로 명시.

## 액션 아이템
1. **[토큰]** 문서 §6 "mute=#6B7684 단일, #8B95A1는 ≥12px/아이콘만" 명문화. 시안 3종 소형 텍스트 #8B95A1→#6B7684 일괄 교체.
2. **[원본 정합]** phones-9.html 초록 세리프 `₩10,000` → Pretendard tabular-nums 무채색 `10,000`(단위 없음).
3. **[카드 CTA]** 시안 카드 상태 분기: 모집중=초록 solid `신청하기`, 대기가능=고스트 `대기 신청`, 마감/신청완료/입금대기=태그. 문서 §4-1에 "카드 좌측 초록 보더·초록 날짜필 = 그린 면화 금지" 추가.
4. **[카피]** phones-missing.html 입금대기 "신청 완료"→"신청 접수됨"+입금 기한. 문서 §5 반영.
5. **[정합성 리스크]** 코드 마이그레이션 plan에 "MeetingCard 링크 구조 분리 + 상태별 CTA" 작업 시 스텝 할인가/마스킹 회귀 테스트 명시.
6. **[텍스처]** grain opacity 상한 ≤.2로 문서 §4-6 수정.

## 미합의 사항 → 해결
- **카드에 가격을 노출할지 자체** — 한결(마스킹·할인가 정합성 때문에 카드에서 가격 제거도 선택지)↔정아름(균일가라 가격은 부차 정보, 노출 무해).
  - **2026-07-07 사용자 결정: 카드에 가격 미노출(B안).** 참가비는 상세에서만. 근거: (1) 균일 소액(대부분 10,000)이라 앵커링 이득이 작고, (2) 카드에 가격을 넣으면 스텝 할인가·정원 마스킹과 얽혀 정합성 리스크. C안(카드에 정가 그어서→내 금액 표시, getDisplayFee로 카드=상세 일치)도 검토했으나 목록 미니멀리즘을 우선.
  - **적용:** 디자인 문서 §4-1에 "모임 카드에는 참가비를 표기하지 않는다(상세에서만 노출)" 명문화. 카드 CTA row는 가격 없이 CTA/태그만. 코드 마이그레이션 시 MeetingCard에서 fee 표기 제거.
