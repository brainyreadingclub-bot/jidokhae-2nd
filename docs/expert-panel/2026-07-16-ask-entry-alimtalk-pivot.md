# Expert Panel: 물어보기 회원 진입 방식 전면 재검토
> 2026-07-16 | 패널 5명

## 질문
지독해(경주·포항 독서모임, 250명)의 무료 인게이지먼트 기능 "물어보기(책 담기)"를 정기모임 다녀온 회원에게 **어떻게 다가가고 어떻게 보여줄 것인가?** 지금 논의된 "지속형 토스트 + 종 점 안전망" 안이 최선인가? 더 좋은 방안은? 놓치고 있는 건?

## 라운드 1: 독립 의견 (요지)

### 🧭 나침반 (PM)
- **핵심**: 토스트+종은 "인앱 진입"을 정교화한 것뿐. 진짜 병목은 회원이 앱을 안 여는 것 → 이미 보유한 알림톡을 진입점으로 승격하는 게 최선.
- **근거**: `getPendingAsk`가 이미 (user,meeting) 미해소 건 + viewed 기록. 모임 하루전 리마인드와 같은 크론 패턴으로 "무슨 책 읽으셨어요?" 알림톡 1건 → 딥링크. 카톡 열람률 >> 인앱 노출. 인앱은 보조 안전망이면 충분, 지속형 토스트는 과설계.
- **리스크**: 알림톡 신규 템플릿 카카오 심사 필요 + 잦으면 채널 차단. 모임당 1회, 미응답 재발송 없음으로 절제.
- **추천**: 지금 켜지 말고 인앱 조용한 카드(B안)만 ON → baseline 측정 + 알림톡 템플릿 1종 심사 병행 착수.

### 🎨 결 (UI/UX 디자이너)
- **핵심**: 지속형 토스트 버리고 기존 인라인 AskStrip을 유일 앱내 진입점으로. 승부는 화면이 아니라 모임 다음날 알림톡 1발.
- **근거**: 현 코드는 이미 심리적으로 옳음(AskStrip=개인 기록 프레임, viewed는 해소로 안 쳐 재노출 안전망 내장 asks.ts:45). 자동소멸 안 되는 검은 토스트(neutral-800)는 하단 탭 가리고 "왜 안 없어지지"를 학습시켜 **다음부터 토스트 전체 무시**. 앱 열어야만 보이는 토스트/종은 북극성에 구조적으로 무력. 알림톡 인프라 비용 0.
- **리스크**: 참여자 전원 매번 발송 시 "책 선정 냄새" 눈치 + 피로. 참여 직후 1회·answered/dismissed skip을 dedup 인덱스로.
- **추천**: 토스트 도입 말고 "모임 다음날 미응답자 알림톡 1회 + 앱 열면 기존 AskStrip". 종 점은 알림톡 미도달자 보조로만.

### 📊 팩트 (데이터 분석가, 반대 관점)
- **핵심**: 지금 UI 정교화는 조기 최적화. 북극성 지표가 계산부터 틀렸고, 진짜 병목은 UI가 아니라 도달(노출).
- **근거**: `getAskStats` 실측 — 분자(book_asks 전량, 165행 필터 없음)와 분모(isAskEligibleMeeting 자격필터+dedup)가 **서로 다른 모집단** → responseRate 부풀거나 100% 초과. 분모에 미노출(unexposed)까지 섞여 "노출×전환 혼합 지표"가 됨. 표본 월 10명대라 answered 1건이 ~7%p 흔듦 → "4주 30% 폐기선"은 노이즈. book_asks는 이미 viewed→answered/dismissed 퍼널 + first_viewed_at 기록.
- **리스크**: 계측 틀린 채 데이터 쌓으면 이후 재분석 불가한 오염 데이터.
- **추천**: 켜기 전 getAskStats를 (1) 노출률=viewed/자격참여 (2) 전환율=answered/viewed 2지표로 분리. 폐기선을 "노출자 30명 누적 시점 전환율 신뢰구간"으로 재정의. UI A/B는 그다음.

### 📣 다리 (PMM)
- **핵심**: 인앱은 부차. 진짜 도달 레버 = 모임 다음날 카카오 알림톡 1종 신설. 메시지는 "기록 초대"로 프레이밍.
- **근거**: notification.ts에 이벤트/크론 발송 + 중복방지·이력 인프라 완비. 6번째 템플릿(meeting_followup)을 다음날 오전 크론으로 confirmed에게 → 앱 안 여는 다수에게 북극성 직접 타격. 오픈채팅은 로컬 특성상 단체방 공지로 희석 + 개인 기록 프레임과 충돌 → 1:1 알림톡(회원명 변수)이 우위.
- **리스크**: 카카오 신규 템플릿 심사(수일) + 정보성/광고성 분류. "개인 독서 기록 안내" 정보성 문안으로 승인, 참여자 1회 제한.
- **추천 메시지 예시**: "#{회원명}님, 어제 『#{모임명}』 어떠셨어요? 함께 읽은 그 책, 서재에 담아두면 올해 읽은 책이 한 권씩 쌓여요. → 서재에 담기" (투표·선정 언급 없이).

### 🗣️ 또렷 (CX/라이터)
- **핵심**: 토스트+종은 IT 기준. 4050 비IT엔 종/토스트가 미지의 UI → 익숙한 알림톡을 1차 진입, 앱 안은 서재 상시 카드를 최종 안전망.
- **근거**: 막히는 3곳 — (1) 검은 토스트를 광고/오류로 읽고 X부터. 종=저장함인 줄 몰라 닫으면 영영 못 찾음. (2) 검색 바텀시트에 "이번 모임에서 읽은 책" 맥락 소실 → "무슨 제목 넣지?"에서 멈춤, 오타/부제/출판사로 0건→포기. (3) 완료 후 "그래서 뭐?" — 첫 1권에선 개인 기록 가치 체감 안 됨.
- **리스크**: 종/토스트 유일 경로면 4050 다수 "닫기"→영구 이탈, 응답률이 IT 편향으로 왜곡.
- **추천**: 모임 다음날 알림톡 1차 노크 "○○님, 어제 △월 정기모임 어떠셨어요? 읽으신 책을 서재에 담아두시면 오래 기억에 남아요 [담으러 가기]". 서재 상단 상시 카드 "△월 모임에서 읽은 책, 담아두시겠어요?". 검색 안내문 "책 제목 일부만 넣어도 돼요 (예: 데미안)".

## 라운드 2: 토론

### 상호 반박 & 보강
- **PM ↔ 분석가**: PM "알림톡 승격" vs 분석가 "그 전에 응답률 계산부터 틀렸다, 지금 켜면 오염 데이터". → 계측 수정이 알림톡보다 앞선 선행 게이트로 수렴.
- **디자이너 ↔ CX**: 디자이너 "토스트 버리고 인라인 AskStrip 유지(재노출 안전망 내장)" + CX "4050은 토스트=광고/오류, 종=미지 → 닫으면 실종". → 토스트·종을 주 진입점으로 쓰면 안 됨. 인앱은 조용한 상시 카드/스트립.
- **PMM ↔ 전원**: "인앱 부차, 다음날 알림톡이 북극성 직접 타격 유일 경로" 전원 동의. 단 디자이너·PMM 공통 경고 — 참여자 전원 매번 발송은 책 선정 냄새 누출 + 피로 → 1회·응답 시 재발송 중단 필수.

### 핵심 논쟁점
1. **지금 켜느냐 vs 계측 고치고 켜느냐** — 분석가만 강하게 "계측 먼저", 나머지 "인앱 먼저 baseline" 경향 → 오염 데이터 논거에 "계측 수정 후 켜기"로 수렴.
2. **알림톡 성격(정보성 vs 광고성)** — PMM 혜택 프레이밍 vs CX 담백 정보 톤. 카카오 심사 분류 리스크로 미해결.

## 최종 합의
진입 방식의 답은 "토스트냐 종이냐"가 아니다. 회원이 모임 사이 앱을 안 여는 이상 인앱 UI는 무엇을 세워도 응답률 상한이 구조적으로 낮다. 이미 가진 카카오 알림톡(5종 운영 중)을 모임 다음날 1발 진입점으로 승격하는 것이 북극성을 직접 때리는 유일한 레버다. 인앱은 기존 조용한 인라인 스트립을 앱 여는 소수용 안전망으로 유지(토스트·종을 주 진입점으로 만들지 않음). 단 켜기 전에 응답률 계측 버그(분자·분모 모집단 불일치)를 반드시 수정하고 폐기선을 표본 기반으로 재정의한다.

## 액션 아이템
1. **[선행·블로킹] `getAskStats` 수정** — 노출률(viewed/자격참여) + 전환율(answered/viewed만) 2지표 분리, 60일 윈도우 분자에도 적용, 회귀 테스트.
2. **폐기선 재정의** — "4주 30%" → "노출자 누적 n≥30 시점의 전환율 신뢰구간".
3. **알림톡 6번째 템플릿 신설** — 모임 다음날 오전 크론, confirmed 참여자, 1회·answered/dismissed면 skip(dedup 인덱스), 딥링크로 물어보기. (notification.ts 패턴 재사용)
4. **인앱 토스트·종 폐기, 조용한 상시 스트립 유지** — 서재 상단 "△월 모임에서 읽은 책, 담아두시겠어요?".
5. **검색 문구 완화** — "책 제목 일부만 넣어도 돼요 (예: 데미안)" + 0건 fallback 강화.

## 미합의 사항
- **알림톡 톤(정보성 vs 혜택)** — 카카오 심사 분류 리스크. 단무지님 + 카카오 절차 확인 필요.
- **알림톡 발송 자체가 운영 정책 사안** — 이 서비스는 "입금 확인 알림 금지" 등 알림 피로에 민감. 새 알림톡 도입은 단무지님 결정.
