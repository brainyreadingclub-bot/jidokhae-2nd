# 걸어둔 자동 작업

> **사람이 누르지 않아도 도는 것 전부를 한 장에 모았다.** 새로 걸거나 끄면 그 세션 안에 여기를 고친다.
> 고치기 직전에 다시 읽고 자기 줄만 고친다.
>
> **값(개수·다음 실행 시각)을 믿지 말고 각 칸의 「세는 법」으로 다시 센다.** 아래 내용은 **2026-10-09에 잰 것**이다.
> 🔴 **「0건」과 「안 돌았다」는 다르다.** 보낼 게 없어 0건인지, 작업이 아예 안 돌았는지는 **실행 기록**으로만 가른다. 데이터베이스에 행이 없다는 것만으로는 갈리지 않는다.

## 1. 서버 예약 작업 — 베르셀(서버 회사)이 매일 부른다

**정본:** `jidokhae-web/vercel.json` (저장소 루트 쪽 파일은 읽히지 않는다)
**세는 법:** `git show origin/main:jidokhae-web/vercel.json`
**돌았는지 보는 법:** 베르셀 `Jaeyoune's projects` 팀 → `jidokhae-2nd` → Logs (옛 팀 `flashcheck's projects`를 보면 0건으로 나온다)

| 한국시간 | 무엇 | 보내는 것 |
|---|---|---|
| 매일 10:00 | 물어보기 (`/api/cron/book-ask`) | 전날 정기모임 참여자에게 「물어보기」 알림톡. **토론모임은 대상 아님** |
| 매일 18:30 | 대기자 환불 (`/api/cron/waitlist-refund`) | 내일 모임에서 승격 못 한 대기자 전액 환불 + 알림톡. 실패 건은 다음 날 다시 잡는다 |
| 매일 19:00 | 전날 리마인드 (`/api/cron/meeting-remind`) | 내일 모임 신청자에게 리마인드 알림톡. 🔴 **모임 유형을 안 가린다** — 토론 신청자에게도 정기 문구가 나간다(10/26 전 새 문구 필요) |

설정은 UTC로 적혀 있다(한국시간 − 9시간).

## 2. 일이 생기면 바로 나가는 알림톡

**세는 법:** `notifications` 테이블을 종류(`type`)별로 센다. 종류 목록의 정본은 `jidokhae-web/src/lib/notification-log.ts`의 `NOTIFICATION_TYPE_LABELS`

| 언제 | 무엇 |
|---|---|
| 카드결제 성공 | 신청 완료 확인 · (정원 초과면) 대기 신청 확인 |
| 확정자가 취소해 대기자가 올라갈 때 | 승격 확정 |
| 프로필 설정을 처음 끝냈을 때 | 가입 환영 — 2026-10-09까지 **0건**(가입자가 없었다. 실패 아님) |

🔴 **계좌이체 경로에는 알림톡이 하나도 없다** — 신청 완료·대기 승격·미승격 정리 셋 다. 메우는 작업이 결정 대기 중이다(`결정대기.md` 「대기 신청 카드 전용」).
입금 확인 때 알림톡을 안 보내는 것은 **의도된 결정**이다(2026-04-23, 월말 몰아 처리).

## 3. 클라우드 예약 — Claude가 정해진 시각에 혼자 돈다

**세는 법:** 세션에서 `RemoteTrigger` `list`, 또는 claude.ai/code 의 Routines 화면
**돌았는지 보는 법:** `RemoteTrigger` `list_runs` → `get_run_log`

| 이름 | 언제 (한국시간) | 무엇 | 상태 |
|---|---|---|---|
| `jidokhae-daily-ops` | 매일 06:07 | **매일 점검 메일.** 한국시간 어제 하루의 알림톡 실패 · 결제 실패 · 0원 확정 · 서버 오류 · 신규 가입 + **환불 대기 누적**을 읽기만 해서 대표님 메일로 한 통 보낸다 | 켜짐 |
| `jidokhae-book-ask-first-send-check` | 일회성 | 물어보기 첫 발송 확인 | 꺼짐(끝남) |

- 점검 메일의 날짜는 **데이터베이스 시계로 한국시간 어제**를 잡는다. 06:07 KST에 서버 시계는 아직 UTC 전날이라, 기계 시계를 쓰면 하루 밀린다
- ⚠️ 서버 오류 항목은 베르셀 연결 권한이 없어 「확인 못 함」으로 나오는 중이다 — 연결을 `Jaeyoune's projects` 팀까지 포함해 다시 해야 닫힌다
- 「결정 대기」 칸은 **아직 메일에 없다** — 붙이는 작업이 남았다
- 같은 목록에 **지독해와 무관한 개인 예약 둘**(평일 저녁 브리핑, 매월 1일 월간 리포트)이 있다. 지독해 작업으로 착각하지 말 것

## 4. 세션 안에서 자동으로 도는 것 (훅)

Claude Code를 쓰는 동안만 돈다. 서비스와 회원에게는 영향이 없다.

**세는 법:** 저장소 `.claude/settings.json`과 `~/.claude/settings.json`의 `hooks`

| 언제 | 무엇 | 어디 |
|---|---|---|
| 세션 시작 | 결정 기록(`DECISIONS.md`)을 읽어 넣는다 | 저장소 |
| 메시지 보낼 때마다 | 보고 규칙(결정 필요 / 한 일, 15줄)을 붙인다 | 저장소 |
| 관리자가 파일을 쓸 때 | 부서 소관 파일이면 막는다 | 저장소 |
| 부서 작업 끝날 때 | 부서 로그를 남겼는지 확인 | 저장소 |
| 명령 실행 전 | 깃허브 계정이 맞는지 확인 | 전역 |
| 세션 끝날 때 | 작업 현황판(cockpit)에 브랜치·미커밋 상태 기록 | 전역 |

## 5. 기록이 남지 않는 것 — 주의

- 🔴 **서비스 설정(`site_settings`)을 바꾼 시각은 어디에도 안 남는다.** 언제 켰는지는 그 작업을 한 세션이 직접 적어야 한다(예: 5탭·서재 2026-10-07 23:15, 토론모임 2026-10-09 11:16 — 인수인계에서 옮김)
