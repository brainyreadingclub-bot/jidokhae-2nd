- **새 기준을 만들지 않았다.** 기존에 같은 것을 세는 정의가 이미 셋 있었다 — "참여 = 결제완료 + 모임일 경과"(프로필), `PARTICIPATED_STATUSES`(`registration-status.ts:18`), `isAskEligibleMeeting()`(`asks-pure.ts:17`). 특히 세 번째는 **물어보기 분모가 이미 "정기모임 실참여"를 세고 있는 것**이라, 자격 규칙은 거기서 **60일 윈도우만 걷어낸 것**이 됐다. 네 번째 정의를 만들었으면 분모가 또 갈라졌을 것이다
- **`meeting_type` null 폴백을 자격에 넣지 않았다.** 지시에 "환불은 정기로 폴백하는데 자격도 같은 폴백인가"가 있었는데, 확인해보니 **그 데이터 자체가 없다** — `migration-meeting-type.sql:28`이 `NOT NULL DEFAULT 'regular'` + CHECK고 TS 타입도 non-nullable이다. `refund.ts:120`의 `string | null | undefined`는 **함수 시그니처의 방어**지 데이터 상태가 아니다. 없는 상태에 분기를 만들면 다음 사람이 "null인 경우가 있구나"로 읽는다
- **필터를 `= 'regular'` 화이트리스트로** 정했다. `<> 'discussion'`은 지금은 같은 결과지만 **2단계 번개가 세 번째 유형으로 들어오는 순간 번개를 정기로 세어버린다**
- **`meetings.status='active'`를 명시적으로 넣었다.** 모임 삭제 시 registration이 전부 `cancelled`로 바뀌므로 이중이지만(`delete/route.ts:95-144`), **일괄 환불이 부분 실패하면 모임은 `deleting`에 멈추고 일부 registration이 `confirmed`로 남는다**(`:152-158`). status 조건만으로는 그 잔재를 못 거른다
- **`is_free`만 우회에서 뺐다.** admin·editor·`is_staff`는 우회시켰다 — 셋은 `isCurator()`와 정확히 같은 집합이라 규칙이 늘지 않고, **발제를 쓰는 사람이 그 모임에 신청 못 하면 앞뒤가 안 맞는다.** 반면 `is_free`는 실제로 정기모임을 신청하므로(pending_transfer) 일반 규칙으로 자격을 얻는다 — 우회를 넣으면 **정산용 플래그가 권한 플래그로 번진다**
- **RPC에는 자격을 넣지 말라고 적었다.** 스텝 할인 슬롯이 FOR UPDATE 락 안에서 재검증되는 이유는 두 사람이 마지막 슬롯을 동시에 집을 수 있어서인데, **자격은 과거 참여로 결정되는 값이라 그런 경합이 없다.** 넣으면 `pricing.ts ↔ SQL 동기 필수` 같은 부담이 하나 더 생긴다
- **플래그 기본값은 선례(`library_enabled`·`next_ui`)를 그대로 따랐다** — 행 없으면 OFF. 세 번째 플래그만 기본값이 다르면 켜는 날 매번 확인해야 한다. 대신 **행은 값과 무관하게 켜는 날 만들라**고 정했다: 행이 없으면 끌 때 SQL을 새로 써야 하는데 **사고 시간에 SQL을 쓰게 두면 안 된다**
- **"끄면 무슨 일이 나나"의 핵심은 돈이다.** OFF는 새로 들어오는 것만 막고, **이미 결제한 신청의 조회·취소·환불은 플래그와 무관하게 살려뒀다.** 끄면서 취소까지 막으면 환불 경로 자체가 사라지고, 결제한 모임이 화면에서 사라지면 회원은 그걸 돈 사고로 읽는다. 자동 환불도 걸지 않았다 — 화면을 내린 것이지 모임을 취소한 게 아니고, **돈을 자동으로 움직이면 되돌릴 수 없다**

**1. 8일 규칙 — `✅ 적용`이 아니다**

`검토문서/2026-08-18-켜는날-런북.md`를 열어 확인했다. §0 사전 조건 표에는 *"다음 토론모임 + 책 연결 + 발제문 선등록"* 한 줄뿐이고 **날짜 규칙이 없다**(`grep "8일" → 0건`). 상태 표의 `✅ 적용` 정의는 *"코드/운영에 반영됐고 **누군가 실제로 겪고 있다**"*인데, 켜는 날 런북을 보는 사람은 이 규칙을 만나지 못한다.

고친 방식: `검토문서/**`는 내 소관이므로 **런북 §0에 행을 직접 넣었다.** 그러고 나니 `✅ 적용`이 참이 됐다. `🔨 미적용`으로 낮춰 적고 넘기는 것보다 이쪽이 낫다 — 한 줄이면 되는 일을 상태로만 표시해두면 그게 다음 주까지 산다.
