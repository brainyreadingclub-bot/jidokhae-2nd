# 속도·버튼 작업 — 화면별로 무엇이 바뀌었나 (Speed Insights 비교용)

가지 `perf/speed-buttons`. 비교 기준선은 2026-10-13 대표님이 준 점수(Vercel Speed Insights 실사용, 최근 7일, 전체 70점).
**병합한 날짜를 기준일로 잡고 그 뒤 7일을 본다.** 그 전 7일에는 새 화면을 켜기 전(10-06~07) 기록이 섞여 있을 수 있다.

| 화면 (기준 점수) | 바뀐 것 | 기대 |
|---|---|---|
| `/` (54) | 온보딩을 마친 회원은 서버 입구(미들웨어)에서 바로 `/home`으로 보낸다. 앱 아이콘 시작 주소와 로그인 뒤 기본 도착지도 `/home`으로 바꿨다(설치된 앱 신원은 `id: '/'`로 고정) | `/` 방문 수 자체가 줄어든다. 남는 것은 온보딩 미완성 회원뿐이라 **점수보다 방문 수 감소를 본다** |
| `/home` (79) | 머리(설정·프로필) 동시 조회, 알림 종 숫자는 나중에 채움. 본문의 서로 무관한 조회 4개(프로필·다가오는 모임·내 신청·알림)를 동시에. 토론 자격 판정은 홍보 카드가 뜰 때만 | 첫 바이트·뼈대 표시가 빨라진다 |
| `/meetings/[id]` (73) | 알림톡 옛 주소는 서버 입구에서 바로 `/meet/[id]`로 보낸다(옛 레이아웃을 그리지 않음) | 이 주소 방문이 짧은 리다이렉트로 바뀐다. **`/meet/[id]` 쪽 방문 수가 늘어난다** |
| `/meet` (70), `/meet/[id]` (79), `/shelf` (86), `/me` | 공통 머리 동시 조회 + 알림 종 나중에(본문 조회는 그대로) | 머리·뼈대가 한 단계 빨리 뜬다 |
| `/talk` | 머리 공통 + 같은 답변 조회 2번 → 1번, 다가오는/지난 토론 블록과 발제·신청 현황 동시 조회 | 본문이 빨라진다 |
| 발제 상세 | 공감·답변 남기기가 누르는 순간 화면에 반영, 실패하면 되돌리고 알림. 같은 내용 답변 중복 저장 막음 | 점수 영향은 작다. 「눌렸나?」 체감 개선 |
| `/shelf` | 완독 토글·물어보기 띠 닫기 즉시 반영 | 위와 같음 |
| `/me` 내 정보 | 저장 즉시 새 값 표시(옛 값이 잠깐 보이던 것 제거) | 위와 같음 |

## 바뀌지 않은 것
- 모임 신청·결제 흐름은 손대지 않았다.
- 취소는 한 군데만: 50% 부분 환불에 포트원 「취소 가능 잔액」 조건을 붙였다(2026-10-14 대표님 승인). 같은 순간 두 번 눌려도 환불은 한 번만 나가고, 늦은 쪽은 「이미 처리됨」. 전액 환불·계좌이체 취소는 그대로.
- 서버 지역·DB 지역 그대로(서울).
