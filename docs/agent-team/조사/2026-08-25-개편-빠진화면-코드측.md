## 0. 결론 세 줄

1. **`(next)`에서 옛 화면으로 나가는 링크는 8개다.** 그중 **5개가 `/meetings/[id]`(모임 상세)** — 신청·결제가 일어나는 곳이다.
2. **상세만 빠진 게 아니다.** 승인 시안 18화면 중 `(next)`에 없는 것이 **6화면**(정기모임 상세 · 신청 확인 · 신청 완료 · 토론모임 상세 · 서재 책 상세 · 남이 보는 프로필). 앞 넷은 설계서 §6이 **범위로 명시**했고, 뒤 둘은 설계서에 근거가 없다.

## 2. 반대 방향 — 옛 화면에서 5탭으로 돌아올 수 있나

**결론: 길은 있다. 그러나 어느 길로 가도 `/home`이다. 모임 탭으로는 못 돌아온다.**

### 2-1. 두 레이아웃이 렌더하는 것

| | `app/(main)/layout.tsx` | `app/(next)/layout.tsx` |
|---|---|---|
| 헤더 | 닉네임 + 운영자 뱃지 + 로그아웃 (`:25-40`) | "지독해" 워드마크 + 알림 벨 (`:31-36`) |
| 하단 | **`<BottomNav />` — 2탭** (`:45`) | **`<NextNav />` — 5탭** (`:38`) |
| 푸터 | `<Footer />` 사업자정보 (`:43`) | 없음 |
| 스킨 | 잉크그린 (`primary-*`, `surface-*`, Noto Serif) | 토스 (`tg-*`, `brand-*`, 산세리프) |

`/meetings/[id]` · `/meetings/[id]/confirm` · `/my`는 전부 `(main)` 아래라 **옛 2탭 나비가 뜬다.**

### 2-2. 옛 2탭 나비의 실제 도착지 (`next_ui` ON 기준)

`components/BottomNav.tsx:6-17`의 탭은 두 개다.

| 탭 라벨 | href | `next_ui` ON일 때 실제 도착지 | 문제 |
|---|---|---|---|
| **모임 일정** | `/` | `app/(main)/page.tsx:18`이 `redirect('/home')` | 🔴 **라벨이 거짓말을 한다.** "모임 일정"을 눌렀는데 홈이 나온다 |
| **마이페이지** | `/my` | `/my` (옛 화면 그대로) | 옛 화면 안에서 옛 화면으로 |

즉 **돌아오는 유일한 길이 `/home`**이고, 그나마 라벨이 틀렸다.

### 2-3. 라벨과 도착지가 어긋나는 지점 4곳

| 파일:줄 | 버튼 문구 | 실제 도착지 |
|---|---|---|
| `app/(main)/meetings/[id]/page.tsx:42` | **"목록으로"** | `/` → `/home` (목록이 아니라 홈) |
| `app/(main)/meetings/[id]/confirm/page.tsx:164` | 홈 링크 | `/` → `/home` (이건 맞다) |
| `components/meetings/MeetingActionButton.tsx:429` | **"모임 일정으로"** (취소 완료 후) | `/` → `/home` |
| `components/meetings/MeetingActionButton.tsx:503` | **"모임 일정으로"** (환불 취소 완료 후) | `/` → `/home` |

**시나리오:** 회원이 모임 탭(`/meet`)에서 정기모임을 눌러 상세로 간다 → 스킨이 바뀐다 → "목록으로"를 누른다 → **모임 탭이 아니라 홈에 떨어진다.** 다시 모임 목록을 보려면 하단 5탭에서 모임을 한 번 더 눌러야 한다. 뒤로가기를 아는 회원만 원위치한다.

### 2-4. `(next)`에 error·loading 경계가 없다

`find src/app -name "error.tsx" -o -name "loading.tsx"` 결과 — `(admin)`·`(main)`에는 둘 다 있고 **`(next)`에는 하나도 없다.** `jidokhae-web/CLAUDE.md`가 적은 컨벤션(*"Each route group has error.tsx and loading.tsx"*)에 어긋난다. `(next)` 페이지 8개는 전부 서버에서 Supabase를 여러 번 부르므로, 한 쿼리가 던지면 **Next.js 기본 에러 화면**(스킨 없음)이 회원에게 보인다. 로딩 중에도 스켈레톤 없이 빈 화면이다.

## 4. 5탭 전 화면이 실제로 뜨는가

### 4-1. 렌더 검증 — **하지 못했다**

**렌더 불가 (OAuth 게이트).** `(next)` 8페이지 전부 `app/(next)/layout.tsx:19`의 `isNextUiEnabled()` 게이트 뒤에 있고, 그 앞에 `src/middleware.ts`가 미인증 요청을 `/auth/login`으로 보낸다. 카카오 OAuth 콜백은 프로덕션 도메인으로 가므로 로컬에서 로그인을 통과할 수 없다. Vercel preview URL은 이번 작업에서 제공받지 못했다.

**대신 검증한 것:**

| 방법 | 결과 |
|---|---|
| `npx tsc --noEmit` | **exit 0** — import 끊김·타입 불일치 0건 |
| `npm run build` | **성공.** 8개 라우트 전부 라우트 표에 등재: `/home` `/me` `/me/notifications` `/meet` `/shelf` `/talk` `/talk/live/[meetingId]` `/talk/topics/[id]` (전부 `ƒ` = 동적 서버 렌더) |
| 코드 전수 읽기 | 8페이지 전부 실제 데이터 조회 + 컴포넌트 렌더. **빈 껍데기 0건** |

**⚠️ 이것으로 확인한 것은 "빌드되고 라우트가 존재한다"까지다. 화면이 맞는지는 확인하지 못했다.**

## 5. 왜 이렇게 됐나 (의도 확인)

공통규약 §1에 따라 "빠졌다"고 말하기 전에 의도를 찾았다.

- **설계서 §6은 상세를 범위에 넣었다** — `meetings/[id]` 상세·신청·결제 → 모임 탭 하위, **스킨만**.
- **승인 시안에 4화면이 그려져 있다** — 참가비·신청 버튼·입금 안내·환불 규칙까지.
- **`DECISIONS.md` 전수 확인 — "상세는 구경로를 쓴다"는 결정이 없다.** `🚫 안 함` 행에도 없다.
- **코드 주석은 재사용을 자인한다** — `TalkView.tsx:127` *"신청 CTA … 구경로 재사용"*, `me/page.tsx:10` *"신청 내역·프로필 수정은 구경로(/my) 재사용 (스펙 §6)"*.
- **`jidokhae-web/CLAUDE.md`가 그것을 사후에 정본화했다** — *"상세·신청·결제는 구경로(`/meetings/[id]`) 재사용 — 결제 로직 무변경"*.

**판정: 결정이 아니라 구현 중 축소다.** 설계서의 *"흐름 로직 무변경, 스킨만"*을 *"흐름도 화면도 무변경"*으로 읽은 것으로 보인다. 그 축소가 어디에도 결정으로 기록되지 않은 채 `CLAUDE.md`에 사실처럼 반영되면서, 다음 사람이 읽으면 **의도된 설계로 보인다.**

> 결정 기록에 없는 축소가 `CLAUDE.md`에 사실로 적히면, 그때부터 그것은 결함이 아니라 사양이 된다. 이번에 단무지님이 시안을 보다 물어보지 않았으면 켠 뒤에 발견됐을 것이다.
