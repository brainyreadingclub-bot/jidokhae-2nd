## 4-2. 🔴 신규 회원의 첫 네 화면 중 셋이 구 스킨이다 (관리자 지적 — 코드로 확인)

**코드가 그렇게 되어 있는 게 맞다.**

| 근거 | 위치 |
|---|---|
| 플래그 ON이어도 **온보딩 미완료자는 새 화면으로 안 간다** | `app/(main)/page.tsx:18` — `if (user && isOnboarded(await getProfile(user.id))) redirect('/home')` |
| 반대 방향으로도 막혀 있다 — 새 라우트에 들어와도 **미완료면 `/`로 되돌려 보낸다** | `app/(next)/layout.tsx` — `if (!isOnboarded(profile)) redirect('/')` |
| 프로필 저장 직후 `router.refresh()` → `/` → 이제 온보딩 완료 → `/home` | `components/ProfileSetup.tsx` |

의도 확인(공통규약 §1) — 이 이중 게이트는 *"전화·실명 없이 결제까지 가는 우회 차단"*이 목적이고 주석에 그렇게 적혀 있다. **게이트 자체는 옳다.** 문제는 **그 앞단 세 화면이 새 스킨으로 안 만들어졌다**는 것이고, 그건 결정이 아니라 **승인 시안 18화면에 로그인·온보딩이 아예 없어서** 시야 밖에 있었던 것이다.

- **기존 회원은 티가 안 난다** — 이미 온보딩을 마쳤으므로 로그인 후 바로 `/home`이다.
- **처음 오는 사람만** 구 스킨 세 장을 연달아 보고 나서 새 5탭에 도착한다.
- 온보딩 화면 셋은 전부 `fixed inset-0` 전면 오버레이라 **하단 탭도 안 보인다** — 스킨 경계가 더 크게 느껴진다.
- 플래그 OFF인 지금은 온보딩 뒤가 구 홈이라 **이음매가 없다.** 이 문제는 **켜는 순간 생긴다.**

고치지 않았다 — 회원 노출 화면이고 시안이 없다(디자인 소관).

## 4. 🔴 찍어 보고 나서 보인 것 — 새 상세에서 마감이 "모집 중"으로 보인다

`27-정기모임상세-마감.png`에 **정원 12명이 다 찬 모임의 참여 행이 「12명 모집 중」**이라고 나온다. 버튼은 「대기 신청하러 가기」다.

| | 구 화면 `(main)` | 새 화면 `(next)` |
|---|---|---|
| 정원 표시 판정 | `shouldMaskConfirmedCount(count, capacity, isPrivileged)` — `MeetingDetailInfo.tsx:18` | `data.showAccurateCount` 를 그대로 — `MeetingDetailView.tsx:32` |
| 마감(`count >= capacity`) | **마스킹 해제 → `12/12명`** (`visibility.ts:24`) | 미신청자에게 **`12명 모집 중`** |
| 신청자 3명 이상 | 일반 회원도 **정확한 숫자** | 미신청자에게 **항상 마스킹** |

`showAccurateCount`는 `lib/meeting-detail.ts`에서 `isEditorOrAdmin || isBookedSelf`다. 즉 **새 상세에서는 신청하기 전까지 인원을 절대 못 본다.**

- 실제 증거 대조: `43-현행홈-플래그OFF-위.png`의 8/26 모임 카드는 `12/12 명 · 마감`으로 나온다. **같은 상황을 새 상세는 "모집 중"이라고 말한다.**
- 🔴 **같은 새 UI 안에서도 어긋난다** — `(next)/meet/page.tsx:71`(모임 탭 목록)은 **이미 `shouldMaskConfirmedCount()`를 부르고 있었다.** 상세 한 곳만 안 거쳤다.
- 의도 확인(공통규약 §1) — `DECISIONS.md`·설계서에 *"토론 정원은 평소 숨기고 마감일만 보인다"*는 방향은 있으나 **`🔨 미적용`**이고, 이번 커밋 로그에도 *"정원 마스킹 규칙은 그대로 쓴다"*고 적혀 있다. 규칙을 바꾸려던 것이 아니라 **호출부가 규칙 함수를 안 거친다.** → 판정: **의도 아님(구현 누락)**
- 영향 범위: `next_ui` OFF인 지금은 **회원 노출 0**. 켜는 날 드러난다.

### ✅ 고쳤다 (관리자 승인 후)

`MeetingDetailView.tsx`가 **`shouldMaskConfirmedCount()`를 거치게** 했다. 새 판정을 만들지 않았다 — 규칙 함수는 이미 있었고 호출부만 안 거쳤다(**PR #64 환불 사고와 같은 모양**).

```
value: shouldMaskConfirmedCount(data.confirmedCount, m.capacity, data.showAccurateCount)
  ? `${m.capacity}명 모집 중`
  : `${data.confirmedCount}/${m.capacity}명`,
```

토론 정원 규칙(평소 숨기고 마감일만)은 `DECISIONS.md` `🔨 미적용` 그대로 두었다 — 이번은 **정기 규칙 복원까지**다.

**바뀐 화면 6장을 다시 찍었다.** 참여 행이 실제로 무엇으로 나오는지 촬영 때 함께 뽑아 기록했다.
