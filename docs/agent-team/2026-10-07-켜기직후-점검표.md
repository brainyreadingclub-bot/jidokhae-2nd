## 1. 🔴 멈추는 법 — **먼저 읽는다**

사고가 나면 **되돌릴 수단부터** 안다. 아래는 **재배포 없이** 듣는 순서대로다.

| # | 무엇을 멈추나 | 어떻게 | 효과 시점 |
|:--:|---|---|---|
| **1** | **새 화면 전체** | `update site_settings set value='off', updated_at=now() where key='next_ui';` | **즉시** (요청마다 읽는다) |
| **2** | **서재·물어보기 + 🔴 내일 아침 알림톡 발송** | `update site_settings set value='off', updated_at=now() where key='library_enabled';` | **즉시.** 크론은 다음 실행 때 건너뛴다 |
| **3** | 코드 자체 | `git revert -m 1 <머지 커밋>` + 푸시 | 2~3분 (배포) |

### 🔴 내일(10/8) 오전 10시 첫 발송을 멈추는 것은 **2번 한 줄이다**

`api/cron/book-ask/route.ts`가 **맨 앞에서** 확인한다(PR #49 실측):

```ts
if (!(await isLibraryEnabled())) {
  return NextResponse.json({ status:'success', message:'Library disabled — skipped', data:{ sent: 0 } })
}
```

→ **`library_enabled`를 `off`로 되돌리면 그날 발송은 0건이다.** 배포도, 크론 삭제도, 사람 호출도 필요 없다.

⚠️ **대가** — 서재와 물어보기 화면이 회원에게서 같이 사라진다. **새 화면(5탭) 자체는 그대로 남는다**(그건 1번 플래그다). 둘은 따로 끌 수 있다.

⚠️ **크론을 아예 빼려면** `jidokhae-web/vercel.json`에서 `/api/cron/book-ask` 항목을 지우고 배포해야 한다 — **느리고 배포를 탄다.** 급할 때 쓰는 수단이 아니다.

## 2. 켠 직후 — 순서대로

### 2-1. 스위치가 실제로 켜졌나 (가장 먼저)

```sql
select key, value, updated_at from site_settings order by key;
```
기대 — `next_ui=on` · `library_enabled=on` · `discussion_meeting_enabled=off`(행은 **있어야** 한다) · `payment_mode=both`.

🔴 **`discussion_meeting_enabled`는 값이 `off`여도 행이 있어야 한다.** 행이 없으면 사고 났을 때 `UPDATE` 한 줄로 못 끄고 그 자리에서 `INSERT`를 새로 써야 한다.

### 2-2. 배포가 성공했나

```bash
cd jidokhae-web && vercel ls --prod | head -4
```
기대 — 맨 위가 `● Ready`. **Error면 그 자리에서 멈추고 되돌린다.** 깨진 배포 위에 스위치를 켜면 원인이 둘로 섞인다.

### 2-3. 회원이 보는 화면이 뜨나 (로그인 없이 되는 것)

```bash
for u in / /meet /policy/meetings /auth/login; do
  printf '%-18s %s\n' "$u" "$(curl -s -o /dev/null -w '%{http_code}' -L --max-time 20 https://www.brainy-club.com$u)"
done
```
기대 — 전부 `200`. 🔴 **`/meet`가 200이면서 내용이 모임 목록인지**까지 본다(스위치가 꺼져 있으면 `/`로 되돌려진다).

### 2-4. 🟨 로그인 뒤 화면 — **관리자가 못 한다**

실서비스 로그인은 하지 않는다(안전 규칙). **대표님이 직접 보신다.**

볼 곳 — ① 홈이 비어 있지 않은가(신청한 모임이 없는 **기존** 회원 기준) ② 안내 시트의 **「둘러보기」가 실제로 모임 탭으로 가는가** ③ 모임 상세 ④ 마이페이지 ⑤ 🔴 **「책 담기」 버튼이 정말로 책을 담는가**(단순 이동이면 빈 서재가 열린다).

### 2-5. 알림톡이 V2 문구로 나가나

```sql
select type, status, template_id, created_at
from notifications order by created_at desc limit 10;
```
🔴 **`status`가 `sent`인지 본다.** `pending`에 멈춰 있으면 발송이 안 된 것이다. `failed`면 `error_message`를 함께 본다.
⚠️ 테스트 신청을 만들었으면 **즉시 정리**한다.

## 3. 내일(10/8) 오전 10시 — 첫 발송

**대상** — 오늘(10/7) 경주 모임 참석자 **12명**. 사상 첫 발송이다.

### 발송 뒤 확인

```sql
select n.status, count(*) from notifications n
where n.type = 'book_ask' and n.created_at >= current_date
group by n.status;
```

| 보이는 것 | 뜻 | 할 일 |
|---|---|---|
| `sent` 12 | 정상 | 없음 |
| `failed` 다수 | 치환 오류 가능 | 🔴 **2번 플래그로 멈추고** `error_message` 확인 |
| 행 0 | 크론이 안 돌았거나 건너뜀 | 배포·`CRON_SECRET`·`library_enabled` 순으로 본다 |

🔴 **중복 방지 때문에 첫 발송이 실패하면 같은 사람에게 다시 못 보낸다**(부분 UNIQUE INDEX). **그러니 실패를 늦게 발견하면 복구가 안 된다.** 10시 직후에 본다.
