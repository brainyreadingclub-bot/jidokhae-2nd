## 착수 전에 확인된 것

### 1번에는 앞선 조건이 하나 있다

잠금 라벨을 카드에서 빼고 **「참여하려고 할 때」로 옮기려면, 그 시점에 말해줄 화면이 있어야 한다.** 그런데 **토론모임 자격 잠금 코드는 아직 0건이다**(`DECISIONS.md` 2026-08-22 행 — 규칙은 확정, 구현 미착수 = 전체목록 **A4**).

즉 지금 라벨만 떼면 **처음 온 회원이 토론 카드를 누르고 들어가서, 아무 설명 없이 신청이 막힌다.** 지금보다 나빠진다.

→ **1번은 A4와 같이 간다.** 순서: A4로 「막고 + 왜 막혔는지 말하는」 자리를 먼저 만들고, 그다음 홈 카드에서 라벨을 뗀다.

⚠️ 이 라벨은 **2026-09-19에 관리자가 붙이게 한 것**이다. 처음 온 회원의 첫 화면에 그분이 못 하는 일만 서 있는 것을 막으려던 임시 처방이었고, 대표님 지적이 더 낫다 — **화면을 설명으로 채우는 대신, 필요한 순간에 말한다.**

### 4번은 사실 확인됨

참가비가 실제로 **두 곳**에 있다 — 정보 칸 `참가비 12,000` + 버튼 `신청하러 가기 · 12,000`. 그 다음 화면(신청 확인)에도 또 나온다. **한 흐름에서 세 번이다.**

### 🔴 4번 B안(회차 줄) — 시안의 숫자가 데이터와 맞지 않는다 (2026-10-06 prod 실측)

시안 문구는 **`경주에서 여는 23번째 모임이에요`**다. 그런데 실제로 세어보면 이 문장은 **두 개의 다른 숫자를 한 문장에 섞어놨다.**

| 세는 법 | 값 (2026-10-06) |
|---|:--:|
| **지난 정기모임 전체** | **24** ← 시안의 「23」은 이 숫자다 |
| **경주** 지난 정기모임 | **12** |
| **포항** 지난 정기모임 | **11** |
| **대구** 지난 정기모임 | **1** |

```sql
select coalesce(region,'(없음)') 지역, count(*) 지난회차
from meetings where status='active' and coalesce(meeting_type,'regular')='regular'
  and date < current_date group by 1 order by 2 desc;
```

**그래서 B1을 그대로 구현하면 두 가지가 일어난다.**

1. **「경주에서 여는」을 유지하면 23이 아니라 12다.** 시안대로 23을 쓰면 **틀린 숫자를 회원에게 말한다**
2. 🔴 **대구 모임에는 `대구에서 여는 1번째 모임이에요`가 뜬다.** 이건 [판단기준 §3](2026-09-21-화면-판단기준.md)의 첫 감점 — *"사람이 적어 보이게 만드는 장치"* — 에 정확히 걸린다. 신뢰를 올리려고 넣은 줄이 **새 지역에서는 신뢰를 깎는다**

**선례가 이미 있다** — `shouldMaskConfirmedCount`가 신청자 3명 미만이면 숫자를 가린다. 같은 패턴으로 **회차가 낮으면 줄을 숨기는 규칙**이 함께 가야 한다. 규칙 없이 B1만 켜면 안 된다.

**셀 수 있는 대안 하나** (판단기준 §1 질문 6 「믿어도 되는 모임인가」를 더 직접 답한다): **서로 다른 참여자 78명 · 누적 참여 247회 · 첫 모임 2026-04-05**. 지역에 매이지 않고, 숫자가 작아지는 구간이 없다.

#### ⏸ 2026-10-07 — **대표님 「일단 패스」. 여기서 멈춘다.** 다만 알아낸 사실은 지우지 않는다

🔴 **되살릴 때 이 블록부터 읽을 것.** 아래는 전부 prod 실측·대표님 확인이고, 다시 조사할 필요가 없다.

| 사실 | 출처 |
|---|---|
| **2026-10-07 정기모임 = 280번째** | 아래 계열 + 대표님 확인 |
| **지독해 시작 = 2022년 6월 3일경** | 대표님 (2026-10-07) |
| **일요일 계열은 끝났다** — 4월엔 수·일 주 2회, 5월부터 수요일만 | 대표님 확인 (2026-10-07) |
| 계산 검산 | 2022-06 → 2026-04-01에 248회 ≈ 200주에 248회 = 주 1.24회. 주 1회 + 가끔 주 2회와 맞는다 |

🔴 **회차는 앱에서 셀 수 없다 — 「과거」에 한해서.** `status='deleted'`인 정기모임 25건 안에 **진짜 계열이 통째로** 있다: `04/01 248 → 04/05 249(유일한 active) → 04/08 250 → 251 → 252 → 253 → 254 → 255 → 04/29 256`, 끊김 없이 연속. **실제로 열린 모임이 맞다** — 돈이 오갔다(`248번째` 8명·89,000 / `250번째` 3명·33,000 / `251번째` 2명·22,000 / `255번째` 1명·11,000, 전부 모임 삭제로 `cancelled`). 3월 14건은 개발 테스트다(유효 신청 0 · 제목이 `결제 테스트 모임` 류).

⇒ `status='active'`만 세면 **7을 빠뜨린다**(273 vs 280). 어떤 「세는 법」도 과거는 못 맞춘다.

🟢 **그런데 미래는 셀 수 있다.** 앞으로 열리는 모임은 전부 앱 안에 있다. **「2026-10-07 = 280번째」 기준점 하나만 박으면 그 뒤로는 앱이 센다** — 운영자가 손댈 일이 없다. 되살릴 때의 설계는 이것이다.

**멈춘 지점** — 문구 A/B 중 택일 대기. A `2022년부터 280번 모였어요` / B `2022년 6월부터, 280번째 모임이에요`. **A 권고**(숫자가 커져도 문장이 안 흔들린다).

근거 전문은 [디자인 로그](logs/디자인.md) 2026-10-06 항목.

**다음에 이 건을 다시 열 때 먼저 볼 것**

- 🔴 **다섯 안이 공유한 전제를 의심해라.** 전부 *"제목 + 인원수 + 이름들"*이라는 같은 뼈대 안에서 표현만 달리했다. **뼈대 자체가 아닐 수 있다** — 명단을 이 자리에 두지 않는다거나, 다른 화면으로 옮긴다거나, 아예 없앤다거나
- 관리자가 던졌다가 *"너무 어렵다"*고 되돌아온 질문(**이 명단으로 회원이 뭘 하길 바라는가**)은 여전히 안 닫혔다. **추상적으로 다시 묻지 말고** 실제 사례나 다른 서비스 화면을 놓고 고르시게 하는 편이 낫다
- 🟡 참고로 한 가지는 그대로 사실이다 — **이 명단은 이미 신청한 사람에게만 보인다.** 「빈자리 압박」처럼 *아직 신청 안 한 사람*을 향한 장치는 이 자리에서는 작동하지 않는다

## 닫은 것

### 5번 — 입금자명 (2026-09-20, `1ea6f90`) ✅

**토스트는 대표님이 취소하셨다.** 완료 화면은 그대로 두고 **입금자명만** 고쳤다.

🔴 **찾다가 더 큰 것이 나왔다 — 복사가 안 되는 게 문제가 아니라 「다시 볼 데가 없다」가 문제였다.**

| 언제 | 계좌 | 입금자명 |
|---|:--:|:--:|
| 신청 직전 | ✅ | ✅ 복사됨 |
| 신청 완료 | ✅ | ⚠️ 맨 텍스트 |
| **나중에 상세에 다시 들어왔을 때** | ✅ | 🔴 **아예 없었다** |

계좌번호는 다시 보여주면서 입금자명만 빠져 있었다. **완료 화면을 벗어나면 되찾을 길이 0**이었고, 입금자명이 틀리면 **운영자가 누가 보낸 돈인지 모른다.** 대표님 지적(「복사되게 해줘」)을 따라가다 발견한 것이다.

**고친 것** — 상세(`MeetingDetailView`)와 완료(`RegistrationDoneView`) 두 곳에 `CopyableDepositorName`(기존 컴포넌트) 배치. 새로 만든 것 0. 관리자가 스샷 2장 직접 확인.

**본인 기준 확인** — `hasPendingTransfer`·닉네임 모두 `user.id`로만 만들어져 남의 입금자명이 뜰 경로가 없다(`meeting-detail.ts:105-111`).

🟡 **남은 것 (이번 범위 밖, 따로 처리)** — **입금자명 조립 코드가 2벌이다**: `lib/meeting-detail.ts:156-157` ↔ `(next)/meet/[id]/done/page.tsx:29-30`. 루트 `CLAUDE.md`는 *"`MeetingDetailContent`가 단일 진입점"*이라 적어뒀는데 **이제 그 자리가 아니다.** 지금은 두 사본이 같은 값을 내고(닉네임이 빈 경우만 갈리는데 온보딩 게이트가 막는다) 이번 변경이 위험을 더하지도 않았다 — 개발·운영이 값을 조립한 줄은 0줄이다. **통합은 별건으로 남긴다.**
