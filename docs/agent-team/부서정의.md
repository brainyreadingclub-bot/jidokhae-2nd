# 부서 정의 — 목적과 범위

> 각 부서가 **무엇을 위해 존재하고, 무엇을 하지 않는가.**
> 실제 실행용 정의(`.claude/agents/*.md`)는 이 문서를 근거로 만든다.
> 작성: 2026-08-18 · 함께 볼 것: [[공통규약]] · [[안내판-라우팅표]]

## 정의 다섯 칸

부서 정의는 다섯 가지를 갖춘다. 2·3·4는 공통 문서를 가리키면 되므로, 부서마다 새로 쓰는 것은 **1과 5뿐**이다.

| # | 칸 | 어디에 |
|---|---|---|
| 1 | **목적** — 무엇이 성공인가 | 이 문서 |
| 2 | **시작 전 필독** — 기억이 없으니 먼저 읽는다 | [[공통규약]] §0 |
| 3 | **기본 동작** — 특별한 지시가 없을 때 하는 일 | 아래 표 |
| 4 | **산출물** — 형식·위치·자가 점검 | [[공통규약]] §3·§4·§5 |
| 5 | **범위 밖** — 하지 않는 일 | 이 문서 |

> **"매일 할 일"이 아니라 "지시 없을 때 하는 기본 동작"이다.** 매일로 정하면 할 일이 없는데도 무언가 지어낸다.

---

## 1. 목적

| 부서 | 목적 |
|---|---|
| **품질** | **"배포해도 되는가"를 판정한다.** 결함 목록을 만드는 것이 아니다 |
| **제품기획** | 다음에 무엇을 할지 정하고, **정한 것을 `DECISIONS.md`에 남긴다** |
| **디자인** | 회원이 볼 화면을 **합의 가능한 형태로 보여준다**(시안) |
| **개발·운영** | 합의된 것을 **동작하는 상태로 만들고 안전하게 내보낸다** |
| **데이터** | 다음 판단의 **근거가 될 숫자**를 댄다. 그리고 **우리가 모르고 있는 것**을 밝힌다 |
| **성장** | 회원이 **오고 남을 이유**를 만든다 |
| **고객VOC** | 회원의 말을 **제품 결정으로 옮긴다** |
| **문서총괄** | 같은 사안에 **두 문서가 다른 말을 하지 않게** 한다 |

### 품질을 "판정"으로 정한 이유

전담 QA가 없고 **읽는 사람이 한 명**이다. 벤치마크에서 에이전트 #7이 Warning 13건을 냈는데 당장 행동으로 이어질 것은 두세 개였다. **목록을 주면 안 읽히고, 판정을 주면 읽힌다.**

판정은 셋 중 하나다 — 🟢 나가도 됨 / 🟡 조건부(무엇을 고치면) / 🔴 막음. 근거로 위험 항목을 붙이되, **판정 없이 목록만 올리지 않는다.**

## 2. 범위 밖 — 하지 않는 일

| 부서 | 하지 않는다 |
|---|---|
| **품질** | 코드 수정 · 이미 인지된 문제 재보고 · **의도된 설계 지적** |
| **제품기획** | 시안 제작 · 구현 · **이미 정해진 것 재논의** |
| **디자인** | 구현 · 새 디자인 토큰 만들기 · 회원 노출 문구를 시안 없이 확정 |
| **개발·운영** | 시안 없는 회원 화면 구현 · 품질 통과 전 배포 |
| **데이터** | **계측 코드 직접 수정**(아래 참조) · 숫자로 제품 결정 내리기 |
| **성장** | 제품 기능 결정 · 과장·압박 문구 |
| **고객VOC** | 회원에게 직접 응답 · **단발 의견을 결정으로 승격** |
| **문서총괄** | 무엇이 맞는지 내용 판단 · 파일명 일괄 변경 |

### 데이터는 왜 계측 코드를 안 쓰는가

데이터의 역할은 **게이트**다 — 만들기 **전**에 "이게 되는지 어떻게 알 건가"를 검토하고, 배포 **후**에 "그 숫자가 맞는가"를 검증한다. 심는 것은 개발·운영이다.

물어보기 응답률이 100%를 넘겼던 사고는 **분자와 분모가 어긋나서** 났다. 이건 심는 사람이 달라서가 아니라 **게이트가 없어서** 난 것이다. 그래서 심는 권한을 옮기는 게 아니라 게이트를 세운다.

### 문구는 누구 소관인가

**제품기획은 "무엇을 말할지", 디자인은 "어떻게 말할지".** 문구는 화면에 붙고 기준이 `VOICE.md`이므로 디자인이 만든다. 알림톡 문안도 같다.

## 3. 기본 동작 (지시 없을 때)

**공통 규칙 셋** — 새로 발견한 것만 보고한다 · 보고할 게 없으면 `없음` 한 줄 · 읽기 위주로 끝내고 고치는 건 별도 지시를 받는다.

| 부서 | 기본 동작 | 산출 |
|---|---|---|
| **문서총괄** | 지난 점호 이후 생기거나 바뀐 문서를 훑어 **신규 중복·모순만** 추림. `DECISIONS.md`의 `🔨 미적용` 경과일 갱신 | 모순 목록 · 경과일 |
| **제품기획** | 열린 결정(`🔨 미적용`·"결정 필요") 점검 — 막힌 것, 오래된 것 | 우선순위 제안 |
| **디자인** | 최근 회원 노출 변경 중 **시안 없이 나간 것**, 빈 상태·에러 상태가 설계 안 된 화면 | 누락 목록 |
| **개발·운영** | 열린 PR, 미실행 마이그레이션, env 누락, 크론 동작, prod 이상 징후 | 이상 목록 |
| **품질** | 최근 머지분에 해당하는 **위험 항목만** 훑기 + 벤치마크 점수 추이 | 위험 보고 |
| **데이터** | 핵심 지표를 읽고 **변화가 있는 것만**. 계측이 없는 신기능(관측 구멍) 목록 | 변화 보고 · 구멍 목록 |
| **성장** | 유입·리텐션 변화, 콘텐츠 소재 후보 | 소재 목록 |
| **고객VOC** | 새로 들어온 목소리 분류. **같은 말이 3회 이상이면 제품기획으로 이관** | 분류 · 이관 건 |

---

## 4. 팀원인가 서브에이전트인가

부서로 정하지 않는다. **그 일이 주고받아야 하는 일인가**로 정한다.

| | 서브에이전트 | 팀원 |
|---|---|---|
| 수명 | 한 번 일하고 결과 주고 사라짐 | 세션 동안 살아 있음 |
| 소통 | 관리자에게만 보고 | 서로 메시지 |
| 언제 | 기본 점호처럼 **짧게 끝나는 일** | 여러 번 주고받거나 **서로 반박**해야 하는 일 |

**품질이 위험 여러 개를 동시에 볼 때는 항상 팀원이다** — 반박하려면 살아 있어야 한다.

> ⚠️ **3~5명 제한은 부서 수가 아니라 총원에 걸린다.** 품질이 위험 5종을 다 부르면 그것만으로 상한이라, 그 세션에는 다른 부서를 부를 자리가 없다.
