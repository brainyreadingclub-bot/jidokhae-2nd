# 번개모임 설계 초안 (2단계) — v0.1

> 작성 2026-08-18. **초안 — 단무지님 검토용.** 확정된 결정(DECISIONS 2026-08-14~17)은 그대로 싣고,
> 미정 지점은 ❓로 표시해 질문 목록(§9)에 모았다. 이 문서가 합의되면 시안 → 구현 계획으로 넘어간다.

## 1. 무엇인가 (확정 사실)

- 회원이 직접 여는 자발적 모임. **이미 실제로 운영 중** — 카톡에서 이뤄지고 서비스엔 없다 (2026-08-14 확인).
- 정기·토론과 결정적으로 다름: **신청이 아니라 참여, 결제 없음.**
- 확정된 결정:
  - 참여 자격 = **정기모임 최근 3개월 내 참여** — 자동으로 잃는 자격이라 화면에 **마지막 참여일 필수 표기**
  - 형태 = **가로로 흐르는 점선 카드** (정기=날짜 축, 토론=표지 — 유형은 형태로 구분)
  - 신고 처리 권한 = 큐레이터(admin·editor·is_staff)
  - 인앱 알림 타입 `flash_opened`·`flash_cancelled` 이미 예약됨(코드·DB CHECK에 존재)
  - 나 탭 카운터 `번개 호스트` 자리 예약됨

## 2. 왜 지금 (목적)

카톡 번개는 흘러가고, 못 본 회원은 기회를 놓친다. 서비스에 담으면 ① 모든 회원에게 공평하게 보이고
② "번개를 연 사람"이 기록되고(카운터) ③ 3개월 자격이 정기모임 참여의 이유가 된다 — **번개가 정기모임의 리텐션 장치가 된다.**

## 3. 회원 흐름

### 3-1. 발견 — 모임 탭
정기(날짜 축)·토론(표지 카드) 아래 **"번개" 섹션: 가로 스크롤 점선 카드**.
카드 내용: 제목 · 일시 · 장소 · 연 사람 닉네임 · 참여 N명. 번개가 없으면 "요즘 번개가 조용해요 — 직접 열어볼까요?" + 열기 버튼.

### 3-2. 참여 (자격자)
카드 → 상세(바텀시트 또는 페이지 ❓) → **[참여할게요]** 한 번 — 결제·확인 절차 없음.
참여 취소도 한 번. 정원 개념 ❓ (§9-2).

### 3-3. 자격이 없는 회원
블라인드 금지 원칙 그대로 — 번개는 보이되 버튼만 잠금:
> 번개는 최근 3개월 안에 정기모임을 다녀온 회원이 참여할 수 있어요.
> 마지막 참여 {N월 N일} — 다음 정기모임을 다녀오면 다시 열려요. [모임 보러 가기]

### 3-4. 열기 (자격자)
입력 최소: **제목 · 날짜 · 시간 · 장소** (필수 4개) + 한 줄 소개(선택).
열리면 전 회원 알림함에 `flash_opened` ("⚡ 새 번개가 열렸어요 — {제목}").

### 3-5. 취소·변경
- 연 사람이 취소 → 참여자 전원 알림함 `flash_cancelled`. 결제가 없으니 환불 이슈 없음.
- 시간·장소 변경 ❓ — v1은 "취소 후 다시 열기"로 단순화하는 안 추천 (§9-3).

## 4. 운영·안전 장치

- **신고**: 상세 화면에 조용한 신고 진입점 → 큐레이터에게 인앱 알림(또는 admin 목록 배지 ❓).
  신고 사유 최소 분류(부적절한 내용 / 사칭·사기 의심 / 기타). 처리 = 번개 숨김 + 필요 시 회원 조치(수동).
- **회원간 만남 리스크**: 결제·명단·연락처를 서비스가 다루지 않음 — 만남 자체는 기존 카톡 문화 그대로,
  서비스는 게시판 역할만. 면책 문구 한 줄 상세에 표기 ❓ 법적 검토(§9-5).
- 운영자 개입: admin에서 모든 번개 조회·숨김 가능.

## 5. 데이터 구조 — 옵션 비교

| | A. meetings 재사용 (`meeting_type='flash'`) | B. 별도 `flash_meetings` 테이블 |
|---|---|---|
| 장점 | 모임 탭 쿼리 하나, admin 조회 재사용 | 결제·정원·환불 로직과 완전 격리, 규칙이 안 섞임 |
| 단점 | fee·capacity·정산 등 결제 필드가 끼어들고, 기존 집계(매출·정산·리마인드 크론)에서 flash 제외 조건을 **전부** 달아야 함 — 누락 = 사고 | 쿼리 한 곳 추가, admin 화면 별도 |
| 판단 | 위험 분산에 불리 | **✅ 추천** — "돈 안 다루는 모임"을 돈 다루는 테이블에 넣지 않는다 |

B안 스키마 초안: `flash_meetings`(id, host_id, title, date, time, location, note, status[open/cancelled/hidden], created_at) + `flash_participants`(flash_id, user_id, created_at, PK 복합) + RLS 읽기 authenticated·쓰기 API 경유.

## 6. 자격 판정

`정기모임 최근 3개월 내 참여` = `registrations.status='confirmed'` AND `meeting_type='regular'` AND `meetings.date >= today-90d` AND `date < today`(경과한 모임).
❓ pending_transfer(입금 확인 지연) 포함 여부 — confirmed와 동등 취급 원칙을 따르면 **포함 추천**, 단 모임일 경과 전 미입금은 제외 (§9-4).

## 7. 플래그·지표

- 플래그: `site_settings.flash_enabled` — 전면개편과 독립적으로 켜고 끔.
- 북극성 ❓ 후보: **월간 번개 개설 수** (기존 카톡 대비 기준선을 단무지님 기억으로 잡기) 또는 번개 참여 회원 수.
- 폐기선: 켠 뒤 2개월간 개설 0건이면 화면 축소.

## 8. 비목표 (v1에서 안 하는 것)

댓글·채팅(카톡이 함), 사진, 정원·대기, 반복 번개, 번개 알림톡(인앱만), 지도 연동.

## 9. 단무지님께 질문

1. **상세 화면**: 바텀시트(가볍게) vs 페이지(신고·공유 링크 가능) — 페이지 추천
2. **정원**: 카톡 번개에서 인원 제한을 쓰셨는지? 없었다면 v1 무정원 추천
3. **변경**: 시간·장소 바꿀 일이 잦았는지? 드물면 v1은 취소 후 재개설
4. **자격에 pending_transfer 포함** 여부 (§6)
5. **면책 문구** 필요 여부 — 간이과세자 법적 검토 때처럼 가볍게 확인
6. 카톡 시절 **월평균 번개 횟수** — 지표 기준선용
