# 알림톡 기존 5종 개선안 — 6번째와 묶어 심사 제출

> 2026-08-06 | Spec | 작성: 총괄 | 결정 필요: 단무지님
> 현재 본문은 Solapi API(`getKakaoAlimtalkTemplates`)로 직접 조회해 확보. 콘솔 복사 불필요했다.

## 먼저 — 개선보다 큰 문제 두 건이 나왔다

본문을 실제로 열어보니, 문구를 다듬는 것보다 **사실관계가 틀린 것**과 **아예 안 나가는 것**이 먼저였다.

### 🔴 A. 리마인드가 미입금자에게 "결제완료"라고 말하고 있다

`MEETING_REMIND` 본문 마지막 줄이 이렇다:

```
■ 참가비: #{참가비}원 (결제완료)
```

`(결제완료)`가 **변수가 아니라 고정 문구**다. PR #44로 리마인드 대상에 `pending_transfer`(입금 확인 전)를 포함시킨 뒤로, **아직 입금하지 않은 회원도 "결제완료"라고 쓰인 알림을 받고 있다.**

두 방향 모두 나쁘다 — 입금을 잊은 회원은 "냈다고 하네" 하고 넘어가고, 이미 낸 회원은 문제없지만 운영자는 누가 어느 쪽인지 알림으로는 구분이 안 된다.

**조치**: `(결제완료)`를 `#{결제상태}` 변수로 빼고 코드에서 `결제완료` / `입금 확인 중`을 주입한다. 템플릿을 둘로 쪼갤 필요 없다.

### 🔴 B. 계좌이체로 신청하면 알림톡이 한 통도 안 간다

`/api/registrations/transfer`에 알림 발송 호출이 **아예 없다.** 카드결제 경로(`confirm`, 웹훅)에만 있다.

지금 서비스는 계좌이체 브릿지로 운영 중이다. 즉 **회원이 신청해도 "신청됐습니다" 알림톡을 못 받는다.** `REGISTRATION_CONFIRM`과 `WAITLIST_CONFIRM`은 승인된 채로 사실상 잠들어 있다.

방증도 있다 — 채널에 `TRANSFER_REQUESTED`, `TRANSFER_WAITLIST_REQUESTED` 같은 **계좌이체 전용 템플릿 4종이 승인까지 돼 있는데 코드가 하나도 안 쓴다.** 만들어두고 연결이 안 됐다.

> 3~6월 알림톡 123건 실패와 같은 계열이다. "보낸 줄 알았는데 안 갔다"가 반복되고 있다. 핸드오프 6번(운영자 발송 이력 페이지)의 근거가 하나 더 늘었다.

**조치**: 문안 문제가 아니라 코드 문제다. 별도 작업으로 잡는다. 다만 **계좌이체 신청 확인 알림을 보낼 것인지**는 정책 판단이 필요하다 — 입금 *확인* 알림은 월말 일괄 처리 때문에 일부러 끄기로 했지만(2026-04-23), 신청 *접수* 알림은 성격이 다르다.

## 채널 정리 상태

승인된 템플릿이 **23건**인데 코드가 쓰는 건 **5건**뿐이다. 나머지 18건은 이전 설계(콩 단위, `/my/reviews` 같은 없는 라우트)나 Solapi 기본 샘플이다.

| 코드 env | 실제 템플릿 |
|---|---|
| `SOLAPI_TEMPLATE_CONFIRM` | REGISTRATION_CONFIRM |
| `SOLAPI_TEMPLATE_REMIND` | MEETING_REMIND |
| `SOLAPI_TEMPLATE_WAITLIST_CONFIRM` | WAITLIST_CONFIRM |
| `SOLAPI_TEMPLATE_WAITLIST_PROMOTED` | WAITLIST_PROMOTED |
| `SOLAPI_TEMPLATE_WAITLIST_REFUNDED` | WAITLIST_REFUNDED |

**주목** — 미사용 중에 `POST_MEETING`이 있다. "오늘의 감상이 휘발되기 전에 짧은 기록으로 남겨주세요" + 버튼 `기록 남기기`. 6번째 템플릿과 **거의 같은 자리**다. 다만 링크가 없는 라우트(`/my/reviews`)고 동사가 `기록`(VOICE.md는 `담다`)이라, 수정하면 어차피 재심사다. **새로 만드는 쪽이 깔끔하다.** 이 템플릿은 나중에 후기 기능을 할 때 이름 그대로 살려두면 된다.

## 공통 — 기존 5종이 VOICE.md를 위반하고 있다

`VOICE.md`(2026-08-03 제정)는 알림톡에서 **느낌표·이모지 금지**다. 실제 본문은 이렇다:

- `모임 신청이 확정되었습니다!`
- `내일 모임에 참석해주세요!`
- `함께할 수 있게 됐습니다!`
- 미사용 템플릿에는 `😆 ☺ 😊 🙂 😦 🏦 💰 ⏰ 📍 📚` 까지

VOICE.md는 이미 단무지님이 제정한 규칙이므로 **개선안은 규칙을 따른다.** 다만 톤이 눈에 띄게 담백해지니 미리 알려드린다.

라벨도 고정표(`VOICE.md` §4)에 맞춘다 — `확정되었습니다` → **`신청 완료`**.

### `원` 표기 제거 (2026-08-07 지시)

금액 뒤 `원`을 전부 뺀다. 단위가 붙으면 금액이 더 강조돼 부정적으로 작용한다는 판단. 인앱은 이미 `formatFee()`가 숫자만 반환하는 규칙이라(`feedback_price_no_won_unit`), **알림톡만 예외로 남아 있었다.** 5종 전부 적용.

- `■ 결제 금액: #{결제금액}원` → `■ 결제 금액: #{결제금액}`
- `■ 참가비: #{참가비}원` → `■ 참가비: #{참가비}`
- `■ 환불 금액: #{결제금액}원` → `■ 환불 금액: #{결제금액}`

`■ 결제 금액:` 같은 라벨이 앞에 있어 단위가 없어도 금액임을 오해할 여지가 없다.

## 개선안 5종

### 1. REGISTRATION_CONFIRM — 신청 완료

**현재**
```
#{회원명}님, 모임 신청이 확정되었습니다!

■ 모임: #{모임명}
■ 일시: #{모임일시}
■ 장소: #{장소}
■ 결제 금액: #{결제금액}원
```

**개선안**
```
#{회원명}님, 신청이 완료되었습니다.

■ 모임: #{모임명}
■ 일시: #{모임일시}
■ 장소: #{장소}
■ 결제 금액: #{결제금액}

▪ 취소는 마이페이지에서 하실 수 있습니다.
```

- 느낌표 제거, `확정` → `신청 완료`(라벨 고정표)
- 취소 경로 안내 추가 — 거절·이탈 경로를 쉽게 (`VOICE.md` L1의 정신)
- 버튼·변수 변경 없음

### 2. MEETING_REMIND — 모임 전날 리마인드 🔴

**현재**
```
#{회원명}님, 내일 모임에 참석해주세요!

■ 모임: #{모임명}
■ 일시: #{모임일시}
■ 장소: #{장소}
■ 참가비: #{참가비}원 (결제완료)
```

**개선안**
```
#{회원명}님, 내일 모임에서 뵙겠습니다.

■ 모임: #{모임명}
■ 일시: #{모임일시}
■ 장소: #{장소}
■ 참가비: #{참가비} (#{결제상태})
```

- **`#{결제상태}` 변수 신설** — 위 A 항목. 코드에서 `결제완료` 또는 `입금 확인 중` 주입
- 느낌표 제거. `참석해주세요`(지시) → `뵙겠습니다`(초대) — 이미 돈을 낸 사람에게 지시할 이유가 없다
- **코드 수정 동반**: `sendMeetingRemindNotification`에 `#{결제상태}` 추가

### 3. WAITLIST_CONFIRM — 대기 신청 확인

**현재**
```
#{회원명}님, 모임 대기 신청이 완료되었습니다.

■ 모임: #{모임명}
■ 일시: #{모임일시}
■ 장소: #{장소}
■ 결제 금액: #{결제금액}원
```

**개선안**
```
#{회원명}님, 대기 신청이 완료되었습니다.

■ 모임: #{모임명}
■ 일시: #{모임일시}
■ 장소: #{장소}
■ 결제 금액: #{결제금액}

▪ 자리가 나면 순서대로 알려드립니다.
▪ 모임 전날까지 자리가 나지 않으면 전액 환불됩니다.
```

- 본문 자체는 문제없다. **빠진 것을 채운다** — 대기 회원이 가장 궁금한 두 가지(언제 알려주나 / 안 되면 돈은)가 없다
- 이 두 줄은 실제 동작과 일치한다(`promote_next_waitlisted` 순번 승격 + 크론 전날 전액 환불). 지킬 수 있는 약속만 적었다
- 버튼 `linkPc`가 `null`이라 PC에서 안 열린다 — 같이 채운다

### 4. WAITLIST_PROMOTED — 대기 승격

**현재**
```
#{회원명}님, 대기 중이던 모임의 자리가 나서 참여가 확정되었습니다!

■ 모임: #{모임명}
■ 일시: #{모임일시}
■ 장소: #{장소}
■ 결제 금액: #{결제금액}원 (결제완료)
```

**개선안**
```
#{회원명}님, 자리가 나서 참여가 확정되었습니다.

■ 모임: #{모임명}
■ 일시: #{모임일시}
■ 장소: #{장소}
■ 결제 금액: #{결제금액} (#{결제상태})
```

- 느낌표 제거
- 여기도 `(결제완료)` 고정 문구다. 대기는 선결제 구조라 대개 맞지만, **계좌이체로 대기 신청한 회원**은 미입금 상태로 승격될 수 있다. 2번과 같은 변수로 통일

### 5. WAITLIST_REFUNDED — 미승격 자동 환불

**현재**
```
#{회원명}님, #{모임명} 모임의 대기 중 승격되지 않아 결제 금액이 환불됩니다.

■ 환불 금액: #{결제금액}원 (전액)
■ 환불 예정: 영업일 기준 3~5일

다음에 더 좋은 기회로 뵙겠습니다.
```

**개선안**
```
#{회원명}님, #{모임명} 자리가 나지 않아 결제 금액을 환불해 드립니다.

■ 환불 금액: #{결제금액} (전액)

▪ 카드 결제는 카드사 처리에 영업일 3~5일이 걸립니다.

다음 모임에서 뵙겠습니다.
```

- **`환불 예정: 영업일 3~5일`을 무조건 단언하지 않는다.** 계좌이체 건은 운영자가 수동으로 이체하므로 그 기한을 보장할 수 없다. 카드사 조건임을 명시하는 형태로 바꾼다 (`feedback_operational_policy_first`)
- `승격되지 않아`는 내부 용어다. 회원 말로 바꾼다
- `더 좋은 기회로`는 이번이 나빴다는 뉘앙스라 뺀다

## 제출 묶음 정리

| 항목 | 심사 | 코드 |
|---|:--:|:--:|
| 6번째 (물어보기) 신규 | 필요 | 크론·env·스키마 |
| MEETING_REMIND `#{결제상태}` | 필요 | 변수 1개 추가 |
| WAITLIST_PROMOTED `#{결제상태}` | 필요 | 변수 1개 추가 |
| REGISTRATION_CONFIRM 문구 | 필요 | 없음 |
| WAITLIST_CONFIRM 문구 + linkPc | 필요 | 없음 |
| WAITLIST_REFUNDED 문구 | 필요 | 없음 |
| 계좌이체 알림 미발송(B) | — | 별도 작업 · 정책 판단 필요 |

> ⚠️ **변수를 추가한 2건은 코드와 동시에 나가야 한다.** 템플릿이 먼저 승인·교체되면 코드가 `#{결제상태}`를 안 보내서 발송이 실패한다. 승인 후 교체 시점에 맞춰 배포한다.
