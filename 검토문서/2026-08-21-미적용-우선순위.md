## 왜 켜는 날로 가르는가

남은 미적용 **19건**을 경과일만으로 줄 세우면 틀린다. 이 프로젝트는 지금 **플래그 하나를 켜는 순간 서비스의 성격이 바뀌는 지점**에 서 있다. 같은 항목이라도 켜기 전이면 "안 만든 것"이고, 켠 뒤면 "회원이 겪는 것"이다.

그래서 기준은 하나다 — **플래그를 켠 직후에 회원이나 돈에 닿는가.**

### 켜는 날에 바뀌는 전제 (사실 확인)

| 확인한 것 | 값 | 어떻게 확인했나 |
|---|---|---|
| prod 토론모임 | **전 기간 0건** | `select count(*) from meetings where meeting_type='discussion'` |
| prod `site_settings` | `next_ui` · `library_enabled` · `notice_text` **행 자체가 없음** (= 전부 OFF) | 같은 세션 조회 |
| 발제·인앱 알림 데이터 | `discussion_topics` 0 · `app_notifications` 0 | 〃 |
| 켜는 날 사전 조건 | BOOK_ASK **승인 완료(8/19)**, PR #50→#49→#53 리뷰 완료 — **당일 머지만 남음** | [런북 §0](2026-08-18-켜는날-런북.md) |
| 켜는 날에 할 일 | 런북 §0 — "**다음 토론모임 + 책 연결 + 발제문 선등록**" | 〃 |

**마지막 줄이 핵심이다.** 지금 토론모임 관련 미적용 항목들이 조용한 이유는 결함이 없어서가 아니라 **대상 데이터가 0건이기 때문**이다. 켜는 날 첫 토론모임을 만드는 순간 전부 동시에 살아난다.
